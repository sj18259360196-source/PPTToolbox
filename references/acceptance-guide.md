# 制作与交付要求

新签发的标准与精修项目保存 `workflow_profile` 时，采用[1.30.4制作流程](standard-refined-1304.md)。页面标注只供制作对照，不执行本文旧合同的标注审核、逐条件对照、文本替换用例或软预算说明。精修独立复建仍按风险触发。极速与历史编号继续本文对应的冻结规则。

新签发极速0.6及标准、精修0.4合同统一直接读取标注文字。完整UTF-8 plan.json为权威内容，辅助Markdown便于人工核查，位置总览图用于核对标注位置。新任务不生成文字明细PNG或图片PDF。标准与精修的外观、编辑深度和检查义务保持，极速0.5与0.6的集中复核与容差按[极速制作与验收](fast-review.md)执行。

`context.annotation_text` 提供 `format`、`file`、`sha256`、`encoding` 和完整 `content`。`context.required_text_files`列出本次必读文件与哈希；正文已完整内联时直接阅读，无需重复读磁盘。紧凑任务的 `required_read_files` 使用 `inline_reference` 指向同一份正文。`must_view_files`仅列需要实际看图的文件，阅读文字和核对位置图分别完成。

实际读过后，按当前模板在 `read_files` 中填写对应的 `file` 和 `sha256`，可记录阅读内联正文或同字节原文件。初始空数组不算阅读证据，不能把文件存在、软件下发或模板字段齐全写成已读。缺正文、哈希变化或尚未实际阅读时保留问题，不提前进入制作。旧合同与已签发编号使用原产物和门槛，不自动迁移。

极速0.4、0.5及0.6均使用标注PNG和plan.json，不要求文字清单截图或PDF。Agent直接读取JSON，查看标注图后登记规划审核。最终按Office整页及必要左右大分区复核，不生成逐组件左右对照。控制器核验最终PPTX结构，默认不执行实际编辑、编辑后布局或保存重开编辑测试。只在用户明确要求时增加专项验证。以下实际编辑条款适用于标准、精修和保留原合同的历史项目。

使用本机PPT工具箱，读取当前项目编号的完整要求和有效设置，按原受管流程登记项目并开始制作。

注册后先完成page_plan中的acceptance_plan，覆盖全部element_scope单元。填写原图坐标、关键外观、实现路线、编辑能力、文字完整原文和适用的替换样本。新三档合同从同一份规划生成plan.json、辅助Markdown和一张位置总览图。旧合同保持原PDF及图片要求。

实际查看acceptance_plan_review列出的原图和标注PNG，逐编号核对边界、拆分、实现路线、编辑要求和风险，再提交观察。标注存在不代表已核验。遗漏、框错位或标签不可读时先修订规划，不能提前制作。默认保存在项目内，不强制用户逐页确认。

N红框表示原生结构，B蓝框表示整体图片，I紫框表示图标，S绿框表示基础样式，R橙框表示风险。颜色只表示职责。标准、精修与旧极速保留文字行位、图标主要轮廓及孔洞、颜色、阴影、渐变和边框的原外观要求。极速0.5与0.6按冻结容差保留准确内容、布局、关系与识别轮廓，轻微装饰差异可如实记录并接受，不省略原图可见的基础样式，不用不同轮廓的同义图标替代。

文字检查首末行、行距、锚点、边距、换行和邻接内容。source_text必须是绑定文字对象的完整逐字原文，不能填描述、片段或多个独立对象拼接的字符串。受控文本组合应说明跨块流动限制。

图标按合同选择合格素材、匹配生成或原生绘制，并核对轮廓、比例、线宽、实心孔洞和独特部件。图片可移动替换不等于内部可改色；原生对象数量不证明外观相似。

最终review_full实际查看当前Office整页、原图对照和每个必查局部，逐目标填写acceptance_checks及blocking_issues。原版外观、内容、编辑后布局和保存重开读回分别检查，不能用属性读回代替看图。存在阻断问题时提交needs_changes，不得填passed。

新项目每个目标还需填写visual_criteria。每条包含稳定id、aspect、reference和requirement。reference描述该区域原图可见的具体特征，requirement说明保留条件。所有目标覆盖layout和color，原生目标还覆盖border、shadow、gradient，原生文字增加typography和content，I类图标增加contour和details。极速0.5与0.6的保留条件使用当前冻结容差，不把轻微装饰差异变成精修义务。原图没有某种效果时写明实际不存在及应保持的状态，不能凭空增加效果。

例如AI卡片不能只登记可编辑。应记录倾斜浮动面板、前后层次、发光线条、底部平台的位置关系，以及这些特征不得被平铺矩形图案替代的要求。文字记录实际换行和对齐关系，阴影记录方向、软硬和强弱，渐变记录方向及明暗关系。不要把普通可编辑能力写成视觉标准。

review_full的每个目标填写visual_comparisons，按criterion_id覆盖全部冻结外观条件。每条分别填写reference_observation、office_observation、difference和status。必须描述实际观察到的区域特征和具体差异，不能重复内容完整、未遮挡、可编辑等通用结论。缺少观察时填blocked；未满足保留条件时填needs_changes，并登记blocking_issues。任一条未通过，目标不能填passed。规划标注核验仍只审核拆分和合同，不提前声称已经看过尚未生成的Office成品。

设置变更导致重新规划时，旧标注和旧观察保留为历史，当前验收索引失效。重新规划并核验后再制作。旧编号的冻结合同不自动升级，新规则用于新编号；不能借重新登记抹掉旧项目的缺陷记录。

受管调用软预算中，极速、标准、精修单页分别为30、45、60次。task.budget_status及toolbox_project_inspect的calls提供本地调用计数，含返修累积，不能当作首轮独立成绩。超出时在当前任务说明或观察中记录具体缺陷、继续理由和新增覆盖，不删除必查项，不自动通过。新极速合同采用本文开头的大分区策略；其他合同保留原看图规则。不设置跨档统一4张窗口或新的图片软预算。

长连接MCP的context_id仅限当前会话。独立CLI按公开schema显式传project，随包入口读取toolbox_context.entry_argv。结果未知时先查状态，不重放写入。所有来源缺口、编辑限制和未解决问题都应保留到交付说明。
