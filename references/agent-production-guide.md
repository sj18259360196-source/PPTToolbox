# 制作 Agent 工作说明

精简版与专业版使用同一份制作要求。在 MCP 中调用 `toolbox_manual({"path":"references/agent-production-guide.md"})`，工具会在本文后附上当前保存的完整要求与目录设置。概况页的编辑制作要求会更新这份内容。读取磁盘上的本文只能看到使用说明；完整要求须通过 MCP 读取，或按 `references/current-desktop.md` 的受管 CLI 读取当前 context 的 `startup_prompt`。

## 开始制作

先读 `toolbox_context({"profile":"production"})` 返回的当前 Skill、实例和权限，再读本说明。按本文末尾的完整要求开展任务，其他手册在当前任务需要时再读。若 context 因用户覆盖而返回 full，保留其中的用户要求，不自行丢弃。

核对参考图与用户的准确要求，按当前目录规则调用 `toolbox_project_bind`。新项目使用 `rebuild_start`；已有项目先读取 `rebuild_status`。检查 `command_status`、`workflow_status` 与 `active_task`，再按 `rebuild_next` 返回的任务执行。每次调用带当前 `context_id`，切换项目后重新绑定。

在项目中保存用户要求原文与素材合同。新项目采用当时的全局默认；已有项目使用 `toolbox_production_settings` 或当前任务返回的项目设置。改动全局默认不会替换已有项目策略。具体对象的最新明确要求优先，设置不授予上传、生图、付费或文件权限。

## 按任务推进

读取当前任务的上下文、响应模板、查看策略与 `must_view_files`。参考原文、数字和图形细节必须实际查看。预检用于定位机械错误，视觉判断和文字核对仍由制作 Agent 完成。提交优先使用 `return_next=true` 接续任务；长结果按任务提供的文件提交方式传送。

阶段切换使用 `stage_context` 和 `toolbox_checkpoint`，也可随受管任务提交打卡。告诉用户已完成的部分、待处理问题和下一步。阶段内不用逐工具打卡。遇到必要信息或授权缺失时说明具体缺口；工具结果未知时先读状态与日志，核对后再决定是否重试。

## 返修与接续

规则未变时无需每个任务重读本文。用户调整要求、制作设置变化或恢复对话时，再读取本说明和当前项目状态。

`rebuild_status` 提供当前受管任务、版本与交付状态，`rebuild_next` 提供下一步任务。以当前返回结果为准，不能把历史交接记录中的完成状态直接当作当前结论。`awaiting_revision` 且 `active_task=null` 时，先按明确修改范围调用 `rebuild_revise`。

项目中的 `HANDOFF.md` 保存接续摘要，可记录已完成内容、待修对象、证据位置和下一步。`ppttool.md` 提供工作链与人工备注，自动记录区由工具维护。只补充实际发生的事实，不另建一份重复的任务状态表，不手改 `workflow/state.json`、token 或自动记录来跳过检查。缺少可读摘要时，先从当前状态和实际文件恢复，不猜写进度。

局部修改沿用当前范围和审查绑定，完成工具要求的复查。共享素材、字体或布局变化可能影响其他区域，按当前任务与差异分析处理。重新进入对话后查看当前必要图片，不预先打开全部历史截图。

## 交付与回访

完成适用的 Office 渲染、全页与重点局部核对，以及实际编辑和保存重开验证。向用户发送最终 PPT、项目位置、已验证的编辑操作与剩余限制。缺少环境或证据的部分明确写未完成，不用整体通过掩盖局部缺口。

先交付并等待用户认可，再分别询问是否保留指定素材、是否学习经验。用户没有同意的内容不写入素材库或经验库。
