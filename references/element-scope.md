# 元素范围合同 v1

本合同扩展现有 `page_plan`、`region_objects`、`source_review`。新模板包含填写入口，旧计划没有该字段时继续按旧规则执行。提交范围后，区域制作、源图审查、冻结构建、场景导入与替换都会检查对应关系。调度顺序、组件编译、视觉复核和 Office 编辑回读继续使用原有流程。

## 页面计划

`element_scope` 包含 `version=1`、递增的 `revision`、用户任务原意 `task_requirement` 和 `units`。每个单元记录以下字段。

| 字段 | 含义 |
| --- | --- |
| `id` / `region_id` | 稳定源内容编号及其制作区域，每个区域至少有一个单元 |
| `owner_id` | 内容归属的父编号，无父级用 `null`，不得循环 |
| `semantic_role` | `page_content`、`reference_artifact`、`decoration`、`unknown` |
| `input_form` | `native`、`raster`、`mixed`、`unknown` |
| `requirement` | 本单元对应的用户要求，不能从输出对象类型倒推 |
| `evidence` / `counterevidence` | 已观察依据及反证核对，无反证时说明核对过什么 |
| `required_edit` | `preserve`、`text`、`geometry`、`data`、`group`、`image_replace`、`unresolved` |
| `source` | 保留栅格时必填，包含项目相对路径 `asset`、文件 `sha256`，可选原图像素 `crop`，格式 `xywh` |
| `native_sha256` | 保留原生内容时必填，使用下文的原生快照方法 |

`semantic_role` 不授予改动权限。相同海报作为例证时可以选择 `preserve`，明确要求改字时选择 `text`。允许生成的独立插图可以选择 `image_replace`；其独立标签继续登记为 `text`。待定项保留在审查清单中，不能签为通过。

父子归属与物理组合分别表达。组合单元可绑定实际 group，子单元绑定组内对象；共享的叶对象必须沿真实的父子归属链，互不相关的单元不得重复认领。同一区域中的外加标注可以属于页面讲解，不能仅因位于海报上方就认定为海报内部文字。保留父项与编辑子项冲突时，重新拆分范围。

### 原生快照

从原输入对象建立逻辑坐标下的快照，调用 `scripts.element_scope.native_digest(objects)`。算法保留文字、几何、样式、组合顺序、关系字段和实际编辑形式，仅排除记录用的 `id`、`evidence`、`notes`，统一整数与等值小数表示。不要对制作后的候选反向生成摘要来冒充源证据。无可靠原生源时继续通过原图观察判断，不能声称有原生快照。

原生与栅格混合的保留内容需拆为可核对单元。当前保留栅格路径要求一张源图片、相同字节、相同裁切、无新增蒙版和显式 `fit=stretch`。缩放位置及最终遮挡仍需视觉审查；哈希相同不代表画面没有被其他对象盖住。

## 区域提交

`scope_bindings` 将当前区域内的全部源编号对应到局部 `object_ids`。组件先按原有规则展开，分组可整体绑定。所有输出叶对象都必须有归属，不能把额外重建的海报文字藏在未登记对象中。

```json
{
  "scope_bindings": [
    {"unit_id": "explanation", "object_ids": ["title", "body"]},
    {"unit_id": "poster_example", "object_ids": ["poster_image"]}
  ]
}
```

图片继续提交 `asset_decisions`。`reference_artifact` 仅在源绑定的保留单元中可用，没有全局豁免。原生正文、图表数据和几何能力按各自要求检查，图片中附加一个可编辑文字对象不能代表整张图片已经完成文字可编辑化。应独立登记图片素材和需要编辑的文字。

## 审查、返修与恢复

`source_review.scope_review` 包含当前 `revision` 及全部单元的 `unit_id`、`status`、`note`。任何待定要求或未通过单元都会阻止整页源审查通过。原生 text 对象全部需要精确 `text_checks`；表格和图表内部文字继续由源审查核对。模板默认待审，不填写自动通过记录。

区域返修保留范围与对应关系。改变范围时使用整页 `revise`，提高版本、保留源编号、重新说明证据，相关检查重新进行。既有编号不得悄悄删除；需要改分区时重新分配 `region_id`。当前版本尚不提供内容编号合并或退役机制。

场景携带范围和完整对象对应关系。整体替换及局部采纳不得丢弃这份记录。源文件参与冻结清单和审查复用摘要。内容或决定变化后，旧审查不能复用。改变对象拓扑和编号时需经页面重规划更新绑定，当前范围合同不推测新的语义归属。

## 验证边界

软件检查已登记要求是否完整对应、实际对象能力是否满足、保留源是否被换掉。Agent 负责结合原图和用户要求识别内容，并主动寻找遗漏和反证。当前没有新增自动视觉分类器，也不把模型的文字解释视为识别正确的证明。直接绕开受管接口修改 PPTX 的外部脚本不受该合同实时约束。

旧合同继续可用，因此没有声明所有历史任务都获得范围保护。新模板和制作手册要求填写新合同。真实页面识别、视觉保真和 Office 内编辑行为分别验收。
