# Office 编辑验证

先用当前候选生成计划，再在新副本上执行。默认各取一个可用的文字、形状填充、表格单元格和图片移动缩放样本。计划会列出实际对象名、原候选哈希和具体操作，供运行前查看。

```text
office.edit-readback --project PROJECT plan --pptx candidate.pptx --outdir evidence/edit-plan
office.edit-readback --project PROJECT run --plan evidence/edit-plan/edit-plan.json --outdir evidence/edit-run
```

需要指定长句、形状颜色、图片替换等操作时，在 `plan` 追加 `--operations operations.json`。字段沿用 `office.edit-readback describe` 的现有合同。传入的操作列表替代默认样本。图片替换需要指定 PNG 或 JPEG、原图哈希、新图哈希、裁切策略及伸缩策略。修改生成的操作文件后须重新生成计划，旧计划会拒绝运行。

当前 `editable_behavior` 任务提供 `edit_preparation`，`prepare-submit` 也会按当前候选重新生成这份只读准备清单。清单绑定项目、版本、冻结场景和候选哈希，列全对象及独立素材要求。`edit_readback.targets` 只是前30项提示，是否截断会明确标记，完整对象在 `edit_preparation.targets`。

准备清单为每个独立素材列出移动、缩放和浅色、深色、目标背景检查；包含图片时还列出替换要求。无旋转的顶层图片，以及单层无旋转、无翻转父组内的无旋转图片，可生成移动缩放建议。分组图片按父组实际比例换算为页面坐标，支持横纵比例不同的缩放。嵌套组、旋转或翻转父组等情况保留待处理原因。未提供真实替换图时，替换草稿保持未完成。

分组图片的操作标记为 `picture_child`，`whole_material_group_tested` 保持 `false`。它只移动、缩放图片子对象，素材根组合的编辑与背景观察仍需完成。准备器直接读取已载入的对象节点，不逐张重开和解码整份 PPT。执行器写入副本前重新核对相同父组约束。

任务中的 `operation_batches` 保存已准备操作，并提供对应 `plan_arguments`。每批最多100项，超过后继续拆批，不截掉后部对象。批次只覆盖已准备部分，执行后仍需补齐清单里的其他要求。独立调用 `plan` 且省略 `--operations` 时继续提供通用抽样，不能据此认为全部素材要求已覆盖。

不同背景和同一对象的冲突操作分别使用副本，避免前一测试条件被后续修改覆盖。清单中的观察保持待完成，实际运行、保存重开和看图后再填写。生成准备清单不会通过任何验收，也不会解除历史失败。

后续可在 `plan` 追加 `--previous evidence/edit-run/edit-run.json`。程序核对上次候选、每个操作、输入输出、渲染图片和 Office／字体环境。相同候选上未改变且成功的操作保留原收据，只执行新增、改变或失败的项。图片替换的素材另按哈希核对。旧收据或图片被改写时直接报错。

候选版本改变时默认安排全部所选操作重测。显式追加 `--reuse-unchanged-slides` 后，工具核对所选页的全部 XML、关系文件、页面顺序及全部共享包文件。该页的文字、遮挡、组合、几何或关系变化会重测整页；共享素材、主题、页面尺寸等变化会重测全部所选项。外部链接和无法确定的环境禁止跨候选复用。长文字溢出也会重新测试。

跨候选复用只减少开发阶段重复抽查，保留原输入、输出和收据，并标记 `equivalent_slide_only`。它不满足正式交付对当前候选的编辑证据要求。完整视觉检查和当前候选交付门禁继续执行。同页局部对象复用尚未开放。

`edit-run.json` 是逐案例目录，每项指向自己的真实收据。新测试在 `changed` 子目录产生编辑副本、保存重开读回和抽查页图片，复用项继续引用原文件。收据不会合并成一份虚构的新输出。提交时附上实际收据、输入输出及图片，视觉结论仍由检查图片后填写。

默认长文字样本只增加少量测试字符，不能据此认定任意长句都能容纳。需要验证具体替换文案时，显式提供该文案。`passed` 表示记录中的属性读回及已测文本框检查通过，`visual_status` 仍为 `pending`。
