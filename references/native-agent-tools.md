# Agent 原生 PPT 工具

这一组工具补充阶段内的制作和返修能力。项目仍通过现有控制器推进，沿用 `start → next → submit → finish`、项目授权、冻结合同和三档验收规则。Agent 根据当前任务选择组件或编辑操作，控制器继续检查范围、依赖、候选文件和复核证据。

先用 `toolbox_search` 搜索具体动作，再用 `toolbox_describe` 读取返回的能力卡。能力卡给出当前参数格式、调用入口、单位、最小示例及限制。创建组件走 `rebuild_probe` 的 `result.components`，修改已有对象走 `rebuild_patch`。不要把能力卡中的单项操作直接当成控制器提交包；外层包仍按当前任务返回的 schema 填写。

带最小示例的能力卡使用 `parameters` 描述该完整示例的参数层级。原生效果旧卡另外保留 `field_parameters` 解释单个效果值；它不能代替 `native.format` 操作包。组件卡使用当前组件请求schema。只用于发现的未实现能力仍明确标记不可调用，不提供可执行示例。

| 能力 | 能力卡 | 可执行动作 |
| --- | --- | --- |
| 形状内文字 | `native.shape.text` | 在同一个可编辑原生形状中保存文字和底板，分别设置文字与形状样式 |
| 文字内部排版 | `native.text.frame` | 水平左中右、垂直上中下、换行、边距、段前段后与行距 |
| 对象布局 | `native.shape.layout` | 按幻灯片、选择范围、对象、区域或坐标对齐；等间距、等中心距、固定间距；统一尺寸 |
| 表格 | `native.table.native` | 范围格式、九种对齐组合、四边边框、填充、行高列宽、合并及有快照的拆分 |
| 形状样式 | `native.shape.style` | 单色或线性渐变填充、轮廓、阴影、透明度；未指定的已表示样式保留 |
| 语义组件 | `native.recipe.<名称>` | 创建下面八类由原生对象组成的常用组件 |

八类组件为 `pill_label`、`title_band`、`numbered_node`、`step_arrow`、`info_card`、`notice_box`、`timeline_item`、`comparison_panel`。前四类使用带文字的原生形状，后四类使用带稳定子对象 ID 的组合。独立 `ops.component` 样件结果提供 `component_manifest`，记录可编辑子对象及其角色。受管任务的 `result.components` 和 `rebuild_probe` 保留普通场景对象及稳定 ID，不额外承诺返回该清单。组合内的单独返修仍受原有嵌套对象限制，需要改结构时显式重新生成组件；时间线不会自动重新排版。

创建样式的填充透明度使用 `style.fill_alpha`，取值 0 到 1。新的 `shape.style.format` 操作统一使用 `opacity`，同样是 0 到 1。历史 `native.format` 保留原有 `alpha` 格式。Agent 应读取所用操作的 schema，避免混用字段。

## 文字宿主与场景版本

场景 `1.2` 新增 `shape.text_frame`，其内容必须从 `text`、`runs`、`paragraphs` 中选择一种。嵌套的 `style` 控制文字，形状外层 `style` 控制填充、轮廓和效果。文字会进入字体检查、原文审核、编辑范围判断和验收清单，实际 PPTX 中保存在形状自己的 `txBody`。

旧场景 `1.0`、`1.1` 的含义不变，不能直接添加新文字宿主。只有需要新能力的创建或表格结构编辑会升级版本。`1.2` 必须声明 `path_base`，可用 `project_root` 或 `scene_directory`；`1.1` 仍要求 `project_root`。独立组件和测试夹具使用 `scene_directory`，受管项目仍按自己的冻结依赖解析。

目前提供 28 种已检查调整参数往返的形状预设。具体名称与参数数量从 `native.shape.text` 能力卡读取。预设仍是 PowerPoint 原生几何，可改颜色、尺寸及已暴露的调整参数。自由路径和复杂插画继续使用相应路径或素材工具。

## 编辑约束

对象居中通过 `layout.apply` 执行，文字居中通过 `text.frame.format` 执行。前者移动对象边界，后者调整对象内部文字。布局请求必须提供观察到的对象边界、明确单位和参照物。参照物可以在授权修改范围之外读取，实际移动或缩放的目标必须全部获准；新布局操作移动组合需要对子对象一并授权。历史 `group.translate` 保持原有组合授权含义。

新表格操作要求整数 `version: 1`。范围 `[r0, c0, r1, c1]` 从 0 开始、包含两端。历史 `table.cell` 和冻结验收中的 `table_cell` 继续从 1 开始。字号、边距和边框宽度使用 pt，布局及表格尺寸使用场景单位。

表格内部的一条网格线同时属于相邻两格。设置或清除边框时，工具同步两格对应的边，保留相邻格的文字及其他格式。同一请求对同一条共享边给出冲突值会在写入前拒绝，后续请求可明确覆盖旧值。

合并保留每格原文、坐标和单元格样式快照。拆分只接受与当前合并区域一致的有效快照，并检查合并后的原文没有被另行改写。导入的快照同样校验范围和完整性。没有快照的历史合并表格仍可读取，不能承诺恢复原来的多格内容。无法完整表示的复杂富文本结构会拒绝合并，避免丢失格式。

当前原生返修限定在可配对的源场景和候选 PPTX。旋转、未表示效果、附着连接关系或无法独立重建的对象会明确拒绝。新布局暂不缩放组合、路径和表格。渐变暂只接受可随形状旋转的线性渐变；其他原有效果仍按各自能力卡调用。

## 验证与后续训练

工具回归基准检查确定性的输入、原生 XML、保存结果和独立重建。真实 PowerPoint 的保存、重新打开、属性读取和页面视觉检查分别记录。工具测试通过不会自动把能力卡升级为全部 Office 场景通过，也不能说明 Agent 已掌握调用策略。

若要评估 Agent，后续应让同一模型在固定任务集上自行发现并调用工具，记录首轮成功率、修复次数、工具次数、时间与原生可编辑性。先用失败轨迹补充能力卡、示例和组件，再考虑模型微调。当前实施不训练或更换模型权重。
