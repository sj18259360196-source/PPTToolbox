# 素材选择的唯一决策规则

当前制作偏好及版本以 [制作设置](production-settings.md) 和当前任务 production_settings 为准。

素材路线先服从页面 `element_scope` 中记录的任务要求。引用作品选择保留时，使用绑定源文件及摘要的 `user_asset` 或 `crop` 路线，图片可填写 `raster_content=reference_artifact`。该类别只对已确认的具体保留对象生效，不能据此免除其他正文、图表和图标的原生编辑要求。已有原生对象按原生快照保留，不转成图片。

图片裁切记录采用原图像素 `xywh`。旧保留素材维持原裁切；已声明的源照片可用 `material_requirement.display` 分离显示裁切、蒙版和适配方式，源文件字节及哈希继续保护。保留对象禁止擦字重绘、生图替换或暗改裁切；明确要求局部修改时，先修订范围并单独记录修改目标。生图请求在启用范围合同时携带 `scope_unit_ids`，保留项和待定项不能成为生成替代目标。详细字段见 [元素范围合同](element-scope.md)。

本文件是当前 Skill 素材选择的权威规则。主入口、素材手册和异形手册均引用此处。工具箱准备参考与交接合同，真实生图由宿主当前可调用的工具执行。

新建参考图项目的插画与保留素材须按[插画要求与素材验收](material-quality.md)登记原始要求来源和素材资格。页面截图清楚、整体可移动都不能单独证明素材合格。源像素保留、独立性、透明要求和参考保真分别核对。白色标签、内部关系与渐隐按原图语义保留。

## 按对象选择，不强制遍历一条阶梯

先看整页背景、分区和前后层次，固定组件来源框、目标框与所属关系，再检查原始素材和已核对资产。先读取当前 production_settings。图片生成优先按参考制作复杂插画、人物与装饰标题；可编辑绘制优先保留内部原生对象。简单线性、粗线条及少量规则部件构成的图标，两种模式都绘制为原生形状或路径。简单插画按模式和实际轮廓选路，已有合格独立素材可复用。照片按原件保留或参考生成要求处理，准确身份与明确保留约束继续有效。用户要求内部编辑或禁止生图时遵从要求，旧项目保留已接受计划，通过范围修订更新受影响组件。图片继续填写 raster_content、raster_reason 和逐项 asset_decisions。

| 对象条件 | 应采用的动作 | 采用前检查 |
|---|---|---|
| 正文、数字、单位、表格、图表轴标签、信息关系 | 原生文本、表格、形状或数据图表 | 内容和方向正确，编辑方式满足要求 |
| 真实校徽、品牌标识 | 优先原始文件或准确裁切，内部编辑明确要求时单独重建 | 核对来源与识别轮廓，生成候选不能自动视为同一标识 |
| 照片、纹理、连续色调画作 | 保留原照或按明确保真要求参考生成，来源如实记录 | 人物身份与事实约束继续有效，检查外部残留、边界、比例与清晰度 |
| 设计花字 | 图片生成优先且整体编辑满足需求时参考生成独立标题；可编辑绘制优先时保留原生对象或路径，明确改字要求使用原生文本 | 原文与设计风格准确，按实际对象说明改字或内部路径编辑能力 |
| 复杂插画裁切会截断尖刺、褶皱或完整轮廓 | 图片生成优先且符合对象要求时生成完整独立插画；可编辑绘制优先时按完整部件拆分原生路径 | 核对数量、姿态、孔洞、尖端与白边连续性；照片另按保真要求处理，准确标识保留身份约束 |
| 轮廓简单或可参数化的组件 | 预设形状与调整柄、拼接、布尔或自由路径，选择适合的一项 | 先查轮廓和连接，再查光效 |
| 复杂发光图标、玻璃、全息或设备透视 | 图片生成优先时生成透明 PNG，可编辑绘制优先时拆分原生路径 | 核对构图、数量、姿态、内部细节、风格与回装位置 |
| 照片或插画原有文字 | 与所属素材一起保留，重新生成的可读文字记录准确原文 | 原照保留时不擦字，参考生成后核对文字与图形关系，模糊字不猜写 |
| 有匹配的官方或许可明确的单项资源 | 与当前参考吻合时直接采用，不要求先生成 | 来源、使用条件、轮廓与风格；不能仅凭语义相似替换 |
| 明确要求内部路径可编辑的复杂图标 | 原生拼接、布尔、自由路径或确含矢量路径的 SVG，并检查在 PPT 内的实际对象形式 | 不能用可移动 PNG 冒充内部路径可编辑 |

用户已经允许本任务的复杂局部生成，且对象满足表中条件时，不要反复等待用户再次授权同一个动作；但不得自行改用未经许可的新外部服务上传私有材料。工具未发现、未获授权、调用失败、产物不合格分别记录。

## 直接参考生成与旧记录兼容

新生成决策在当前设置与对象要求允许时采用 `content_category`，填写组件类别、编辑要求、参考局部和理由。简单插画、复杂插画、装饰标题及符合保真要求的照片支持 `image_replace` 或 `group`，图片可以整体移动、缩放和替换。可编辑绘制优先或具体对象要求内部编辑时，制作真实原生路径，不额外制作隐藏备用矢量稿。

`generation_decision` 共用 `scripts/material_routes.py` 的 `DECISION_SCHEMA`。以下只示范字段，参考路径须对应项目内实际文件。启用页面范围时另填写当前组件的 `scope_unit_ids`。

```json
{
  "action": "request_asset",
  "request": {
    "id": "illustration-01",
    "purpose": "复现复杂插画组件",
    "prompt": "参考局部生成独立透明素材，保持构图、姿态、数量、内部细节与原有文字，页面外加标注单独制作",
    "transparent": true,
    "allowed_approximation": true,
    "multi_icon_sheet": false,
    "generation_decision": {
      "basis": "content_category",
      "reference": "input/reference.png",
      "content_type": "complex_illustration",
      "required_edit": "image_replace",
      "text_ownership": "embedded",
      "embedded_text": [{"text": "填写参考内可辨识原文", "legibility": "readable"}],
      "reason": "复杂组件采用参考生成，当前要求为整体替换"
    }
  }
}
```

用户明确要求直接生图时 `basis` 可填 `user_request`。历史 `low_similarity` 继续要求实际绘制稿与低于 75% 的 Agent 判断，分数只对应局部观察。新类别路线不要求分数。宿主工具、参考上传权限及项目限制继续按 `toolbox_material_policy` 执行。

生图优先使用真实透明背景。插入时用 `source_kind=generated`、`raster_content=generated_illustration`，保留原决策并逐项填写 `asset_decisions`。复杂图标用 `asset_role=icon`，插图与图片标题用 `decoration`。生成照片使用 `raster_content=photograph`、`asset_role=photo`、`source_kind=generated`，决策类别声明 photograph。简单图标两种模式均原生绘制，具体对象例外另引用明确要求。独立页面文字和关系线保持原生。

文字归属由组件关系与设计用途确定，OCR 字符和坐标包含关系不能单独作为依据。`text_ownership=asset_title` 表示图片标题，`embedded` 表示素材内部原有文字。可辨原文写入 `embedded_text`，不可辨项用 `legibility=unreadable` 和空 `text`。声明为 `decorative_title` 的装饰标题必须使用 `asset_title`，至少声明一项准确可辨原文。保留原照时，照片文字随源像素保留；重新生成的文字须查看实际图片并提交 `material_text_checks`，每项含 `object_id`、`asset_sha256` 和按声明顺序填写的 `observed_text` 字符串数组，原文与标点完全匹配才可通过，同时完成 `scope_review`。原件保留的照片不做生成文字检查。图片文字无需逐字编辑测试，整体移动、替换和保存重开仍须验证。

## 一张素材板对应多个组件

多个独立小素材可用一条 `request_asset` 的 `request.items` 合图生成。设置 `multi_icon_sheet=true` 与 `transparent=true`，每项填写稳定 `id`、`purpose` 和自己的 `generation_decision`，按需要补 `target_bbox_xywh`、`min_subject_pixels` 与 `scope_unit_ids`。每批最多八项，一项也可用于局部补做。`request_assets.requests` 是多个任务的原子提交，不能据此宣称只调用一次生图。

合图要求相同风格、足够有效像素与透明间隔，不把编号画入图片，不把独立图标合成新场景。生成后按实际主体确认整数像素 `crop=[x,y,width,height]`，逐项检查完整轮廓、透明边缘、身份与文字。通过生成交接的 `crops.template.json` 填写 `sheet_sha256` 与各项 `id`、`crop`、`status`、`note`、`viewed_files`，交给 `generation-ingest --crops`。状态使用 `accepted` 或 `retry`，前者只记录裁切采用决定，视觉与 Office 验收另行完成。

保存真实源板与裁切清单，通过项登记独立 PNG。失败项继续待做，仅补生成对应项，不能复用旧源板裁切坐标。完整生成结果先恢复文件和登记记录，空白工具显示不直接触发重生成。母女等共同构图按一个组件生成，需要分别移动时再拆分。

## PNG 与 SVG 分开

PNG 生图使用实际可调用的图像工具；编写、描摹或矢量化 SVG 是另一种操作，不假设图像工具支持输出真正的 SVG。将 PNG 改后缀或嵌入 SVG 不会得到内部矢量路径。插入 PPT 后的 SVG 也必须检查对象形式。

## 给 Agent 的可选方法建议

背景的规则色块和渐变使用原生形状重绘。照片主体与底色粘连时，可考虑抠图或透明边缘清理。简单图标使用组合形状或原生路径；插画选择绘制路线后，已有干净的黑白语义蒙版可用项目内 icons_trace_fragment，再核对轮廓和孔洞。复杂纹理按图片用途规则处理，不必强行转成大量节点。

上述方法目前只加入制作建议，没有新增自动背景重绘、抠图或插画矢量化引擎。Agent 根据当前工具、已有授权、参考保真要求和投入选择，缺少入口时如实说明。采用生成或重绘后应核对主要轮廓、数量、方向、颜色、构图及回装效果；不能把近似细节当作原始素材。

## 每条路线都要回装检验

登记参考和产物 → 检查真实文件 → 必要的透明与边缘处理 → 放入目标页面 → PowerPoint 导出 → 对应局部左右对照 → 采用或修订。

局部图片可以承载复杂质感和所属素材的原有文字。页面独立正文、数字、表格与关系线保持原生。左右图核对内容与风格，叠图核对位置、比例和遮挡，不自动配准掩盖回装误差。生成补全属于合成近似，不能宣称找回被遮挡的真实照片细节。

## 图标与插画必须记录采用理由

当前任务提供 `asset_decisions` 和生成请求示例。需要检查残字、白色描边、模糊补丁、孔洞和实际轮廓。依据组件类别与编辑要求选路，候选偏差须具体记录并返修，不能只因耗时跳过内容核对。

保留原插画可以避免重新生成改变构图和风格，这是选择依据而非保证效果的证据。未实际生成候选就不能宣称生成一定更差。可在同页对关键失败局部生成候选；不必全页所有图标重做，也不必为了测试接口替换真实Logo。

asset_decisions只是模型记录，不能证明工具调用。真正生成要有实际工具调用、真实产物和来源；不得把尚未查找入口写成无生图能力。

## 素材持久授权

读取 toolbox_material_policy 或 context.material_policy。联网搜图、宿主生图、上传必要参考局部默认允许，项目可以覆盖全局设置。允许值是用户保存的授权，不重复询问；用户当前明确限制优先。不开通新的付费服务，不扩大到未经许可的新服务或无关资料。宿主工具不可用时报告能力缺失。
