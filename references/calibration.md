# Bounded Calibration

The managed interfaces are `rebuild_calibrate_plan`, `rebuild_calibrate_step`,
and `rebuild_calibrate_report`. Their strict schemas are generated by
`toolbox_manager/contracts.py`. The same CLI accepts:

```text
python manager.py --data-dir <isolated-manager> execute --tool workflow.calibrate_plan -- --project <authorized-project> --request <authorized-request.json>
```

Plan binds the current task, revision, scene/PPTX hashes, reference assets, fixed
full-page ROI, background segmentation, parameter bounds, line constraints and
the frozen metric/code version. Geometry and text parameters use points.
Optional `critical_dimensions` (maximum four) freezes a target object's visible
edge or line edge, full-page ROI, pixel tolerance and source attribution.
Supported features are `left`, `top`, `right`, `bottom`, `line_left`, `line_top`;
line features use zero-based `line_index`. The program measures the reference,
not a caller-supplied target coordinate. Use observed/measured sources; inferred
or unknown critical targets require review. This is not a typography baseline.
The first implementation supports single-page, unrotated top-level native text
and ordinary shapes, at most three objects and four scalar parameters.

Step accepts only a calibration ID and durable request ID. The program chooses
absolute candidates using finite enumeration, coarse-to-fine coordinate search
and a small width/font-size block. Each trial starts from the original baseline.
There is no caller-supplied next vector, automatic adoption or automatic review.

The cumulative project-region budget is 24 attempts and 40 exported pages,
including repeated baseline and final verification exports. Each step reserves
at most four exports. Unknown side effects retain their reservations and must
not be replayed. Replanning does not reset the project-region budget.

Report reads existing records only. Fixed-coordinate foreground bounds,
projection and symmetric pixel errors are diagnostics, never a fidelity
percentage. Empty foreground is unmeasurable. Typographic baseline and per-glyph
font resolution remain unknown.

Metric `fixed-foreground/3` preserves the version-2 score formula and weights.
Declared critical edges must not exceed the larger of baseline error and frozen
target tolerance. A poor baseline can improve gradually without immediately
meeting target; a clean baseline stays within tolerance. Repeated-baseline edge
noise above 0.5px or uncertain visible-line correspondence requires review.
Noncritical diagnostics need not all improve monotonically.

`numeric_ranking`/`numerical_best` are score diagnostics, not recommendations.
`recommendable_best` (also `best`) requires existing hard checks, reliable
critical checks and meaningful aggregate improvement. `qualification` explains
each candidate's eligibility or rejection. `target_met` additionally requires
all declared critical tolerances. No declared dimensions means only the existing
scope is protected, not implicit alignment promises. Old/unversioned or stale
records retain `historical_best` but return `needs_review`, never silent approval.
Actual adoption still requires independent verification and visual observation.

Before new baseline exports, fewer than six remaining pages stops conservatively
with `budget_exhausted`, leaving the ledger unchanged. This is minimum search
and final-verification headroom, not permission to reset a repair episode.

Only a legal best candidate with independent save/reopen and scene rebuild
evidence can enter existing `rebuild_adopt`. Actual host observation must include
the reference, baseline, all comparison views and independent final renders.
Original workflow gates and review invalidation remain in force.

The current implementation and acceptance limits are tracked in
phase-three status（本地验收记录未随包提供）. Do not infer Office
acceptance from deterministic tests or from command completion.
