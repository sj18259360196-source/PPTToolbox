# 矢量空间实验版

矢量空间使用独立项目、候选文件和交付记录。界面只需选择输出格式，复制提示词后连同参考图发给 Agent。Agent 决定项目名称、画布和附件路径，再提交结构化 JSON。编译器生成 SVG、PNG 预览，以及当前内容与运行环境支持的 PDF、Illustrator 兼容 SVG、EPS 和 PSD。该链路不调用 PowerPoint 构建或 Office 渲染。

实验入口默认关闭，所有者在设置中开启后才能签发新请求。已有 VEC 请求继续保留原始选项与哈希，不会因为新增格式而改变。

进入页面即可查看完整提示词预览，选择格式后正文同步更新。路径和设置值沿用制作准备首页的颜色。点击复制才签发正式 VEC 编号；更改格式后恢复预览，旧编号对应的内容保持原值。

矢量项目和 PPT 项目共用项目列表、搜索、分类、排序、整理、归档与空间统计。打开矢量项目后使用相同的项目工作台布局，显示参考图、当前预览和运行路径、项目文件、制作记录、助手摘要四个页签。默认显示最新交付，可切换到历史版本；候选、审查、交付和源文档都按版本关联。路径与哈希保存在折叠详情中。

运行路径沿用 PPT 的流程图和节点详情，按记录展示签发、冻结画布与参考资料、版本提交、源文档、结构检查、各格式导出、看图检查、交付以及已登记的中断处理。选择节点可查看时间、结果、依据与下一步，并跳转到对应文件、制作记录或助手。切换版本后，制作节点只读取该版记录；PPT 资源等待、当前矢量服务和管理助手另列为全项目当前状态。没有记录的 Agent 分析或绘制步骤不会补写，结构通过、文件摘要一致和 Agent 看图声明各自保留原来的含义。

所选版本的状态结合本版导出、最后一次检查及交付记录显示，项目当前状态另行保留。当前项目已交付时，旧版仍可能失败或被要求返修；旧版已交付时，新版也可能尚待检查。没有交付时默认选最新候选，有交付时默认选最新交付；新版尚未交付可从版本选择器查看。源文档、预览、成品或清单缺失及哈希变化会显示局部待核对，不把原来的交付记录抹掉，也不继续显示该文件已核对。

结构失败时，先修正文档，再由制作 Agent 使用新请求提交版本。结构检查仍在运行时等待完成；结果未登记时核对版本提交与导出记录。结构通过后仍须看图。各格式分别显示生成、不支持、失败或文件异常；PNG 可用而尚无检查时显示等待实际看图。部分交付保留未完成格式和原因，不视为全部格式已完成。

图中连线表示已保存合同的依赖或记录归属。时间相邻不会自动成为因果，当前服务和助手节点也不连接到历史交付链。运行路径复用当前工作台已读取的记录，不另开编译 worker，也不补做检查或交付。

关闭实验入口后，已有矢量项目仍可查看、下载、整理、归档和核对中断记录。PPT 的执行、审查与交付继续使用原流程；矢量编译和格式交付使用独立接口。

项目名称、分类、排序与归档属于管理元数据，改动不会重写冻结画布、参考资料、格式或候选。改变这些制作选项需要新项目。项目文件页按所选版本提供已登记源文档 JSON、输出、交付清单及伴随源文件，下载前核对安全范围和文件摘要；读取失败显示具体问题。矢量项目不使用 PPT 的批量交付或历史清理功能。

新建页只负责格式选择与提示词签发，已有项目统一从项目列表进入。旧版详情链接会转到共用工作台，并保留所选版本和页签。顶栏刷新作用于当前项目；退出页面时会撤销该页的刷新入口和轮询。

PPT 与矢量项目的新目录必须互不包含。历史目录中已经嵌套的项目保留原位，文件清单、空间统计与 PPT 历史清理按各自登记边界处理，父项目不能读取或删除子项目资料。PPT 项目之间原有的父子关系继续保留。

初始化会在创建目录前保存本次编号、目标目录、画布与参考文件摘要。复制或登记中断后，使用原编号和完全相同的参数重试 `vector_start`，只补齐尚未完成的步骤。已复制的参考文件会重新校验，中断复制的临时片段留在本项目初始化记录中。文件被修改、出现不明文件或冻结选项不同，重试会停止并保留资料。历史版本没有初始化记录的残缺目录仍需人工检查，程序不会猜测或重放原操作。

管理助手可读取矢量制作事实、核对已记录文件、保存项目备注并准备交接材料。摘要沿用已有 API 设置和调用预算，执行状态与管理备注分别保存。制作记录或备注变化后，旧摘要显示待更新。矢量工作图编辑、Office 写入、PPT 场景预检与阶段打卡不适用于此项目，工具会明确拒绝。管理操作不自动编译、检查画面或生成交付。

助手摘要、备注和任务结果属于全项目当前管理记录，切换到旧版时不会变成该版当时的助手活动。排队与处理中显示当前任务状态，残留的摘要失败标为上次摘要整理错误；其他状态标为摘要整理错误。当前读取失败另显示管理记录暂不可用。关闭助手或未配置连接时，可继续查看已保存摘要及其来源是否变化，不显示助手仍在处理。

助手只能读取工具箱已记录的事实、调用与受管文件，无法观察宿主内部思考或未登记的 Adobe 操作。运行路径与工作台验收覆盖本地编译、隔离 Worker、假 provider 和界面行为；没有新增真实模型效果、Illustrator、Photoshop、CorelDRAW 或 Office 验收结论。

## 已实现的格式

| 内容 | SVG | PNG 预览 | PDF |
| --- | --- | --- | --- |
| 路径、矩形、椭圆、直线、分组和矩阵变换 | 支持 | 支持 | 支持 |
| 透明背景、纯色、描边、对象透明度和孔洞 | 支持 | 支持 | 支持 |
| 分组整体透明度 | 支持 | 支持 | 明确返回 unsupported |
| 线性渐变 | 支持 | 支持 | 明确返回 unsupported |
| 保留文字对象 | 支持，依赖已安装字体 | 按当前宿主字体渲染 | 明确返回 unsupported |
| 自动文字转曲 | 未实现 | 未实现 | 未实现 |
| 嵌入图片或外部资源 | 不接受 | 不接受 | 不接受 |

PNG 使用延迟加载的 `resvg_py`。PDF 使用延迟加载的 PyMuPDF 原生 SVG 转换，校正页面物理尺寸，再检查单页和零图片资源。缺少相应运行库时，该格式返回 `unsupported`，不会下载依赖或改用位图 PDF。

| 兼容输出 | 实际文件与可编辑范围 | 当前限制 |
| --- | --- | --- |
| Illustrator 兼容 SVG，协议 ID 为 `ai` | 输出 `document.illustrator.svg`，保留 SVG 路径和文字对象 | 原生 AI 格式未实现，交付保留 `.svg` 扩展名；Illustrator 实际导入与编辑尚未验收 |
| EPS，协议 ID 为 `eps` | 输出真实 EPS，包含矢量路径 | 仅接受不透明纯色图形，不支持文字对象、渐变和透明效果；目标编辑器未验收 |
| PSD 像素图层，协议 ID 为 `psd` | 输出真实 PSD，每个顶层对象或分组成为独立像素图层，并附带矢量 SVG 源文件 | PSD 中的文字和形状已栅格化，不能按文字或矢量形状编辑；Photoshop 实际打开与编辑尚未验收 |

PSD 依赖当前运行环境已有的 `resvg_py` 与 Pillow。某个格式不支持当前内容或缺少依赖时，编译结果保留具体原因，其他格式仍分别记录。CDR 导出尚未实现。

本机实测发现 PyMuPDF 的 SVG 转换会丢失渐变颜色，也会错误处理重叠子对象的分组整体透明度，因此当前编译器直接拒绝这两类 PDF。PDF 文字转换也未开放。遇到这些内容时保留 SVG，并查看 PNG 预览。

SVG 中的文字保留为 `<text>`。指定字体必须出现在当前 Windows 字体注册表中，找不到时验证失败。字体不会打包进文件；其他电脑仍需要相应字体。`outline` 选项只接受已经提供的路径对象，提交文字对象会失败，系统不会自动转曲。`mixed` 保留给后续扩展，当前仍拒绝图片对象；受管请求只开放纯矢量模式。

## Agent 操作顺序

1. 从界面签发的请求读取 `prompt_id`，调用 `vector_prompt(prompt_id)`。核对格式和文字选项，并查看聊天中实际提供的参考图。
2. 界面新请求使用 `agent_setup=true`。Agent 根据参考图比例决定 `canvas`，把附件解析为本机绝对路径并放入 `references`，再调用 `vector_start(prompt_id, name, canvas, references)` 创建独立项目。画布与附件在开始时冻结，重试必须保持相同。历史请求继续使用所有者签发的固定画布与参考文件。项目目录沿用原有授权；既有 PPT 项目不能切换成矢量项目。
3. 根据参考内容编写下述 JSON。调用 `vector_submit(project, document, request_id, formats)`。`request_id` 标识一次提交，同一标识不能提交不同内容。
4. 调用 `vector_status(project)`，检查各格式的 `created`、`failed` 或 `unsupported`。根据 `must_view_files` 打开当前候选的实际 PNG。
5. 查看图像后调用 `vector_review(project, candidate_id, viewed_files, findings, accepted)`。`viewed_files` 填实际查看过的绝对路径，必须包含当前候选 PNG。`findings` 写具体观察结果。需要修订时设 `accepted=false`，修改 JSON 后使用新的 `request_id` 再提交。
6. 当前候选本版审查通过后调用 `vector_finish(project, candidate_id, formats)`。保留签发时的全部请求格式，逐项记录其状态和哈希；至少有一种请求的文档格式可交付，才能登记交付。只完成部分请求格式时，交付状态为 `partial`。

上述名称为 MCP 工具名。内部服务操作名对应 `vector.prompt.read`、`vector.start`、`vector.submit`、`vector.status`、`vector.review` 和 `vector.finish`。界面签发需求由所有者操作完成，Agent 无权替换已签发选项。

`vector_finish` 必须保留签发时请求的全部格式。某个格式不可用时，记录部分交付并保留失败原因，项目仍可继续提交修订。PNG 只用于预览，单独生成 PNG 不能完成交付。兼容输出使用实际文件扩展名，PSD 的 SVG 伴随源文件会一同校验、复制并提供下载。各格式交付记录区分结构检查、PNG 预览检查和目标编辑器验收，SVG 预览通过不等于 PDF、EPS、PSD 画面或 Adobe 软件编辑通过。

完整交付后也可以在同一项目提交新版本，原交付与检查记录保留。每次修订或失败后的重新编译使用新的 `request_id`，相同编号只返回原候选的结果。新版本需要自己的 PNG 看图记录，不能沿用旧版认可。新增检查与首次交付只接受当前成功候选；切换到历史版本查看不会重新开放这些操作。调用 `vector_finish` 时明确填写 `candidate_id`；已有多个候选时，省略编号会被拒绝。重复交付历史候选会在 `finished_delivery` 中返回它的原交付，当前候选与最新交付保持原样。已经交付的候选不能改写检查结论。

检测到仍在运行的受管 PPT 调用时，矢量提交返回 `waiting_for_ppt`，不会创建候选或占用 PPT 锁。返回的 `ppt_priority.blockers` 列出对应项目、调用和处理方式。进程身份无法确认或 Office 写入锁仍需核对时，也会等待并说明原因。Office 锁保留原样，进程已退出不自动证明其 Office 子任务已结束。

已退出的历史调用即使结果仍为 `outcome_unknown`，也不再占用独立矢量任务的执行机会。历史结果、原项目写入保护与重试限制保持原值。检查在本机按进程创建时间排除已被复用的旧 PID，其他主机的旧 PID 不当成本机进程。Windows 进程查询受限时补查进程列表，仍无法确认才返回待核对状态。

调用方需在阻塞原因解除后重新提交相同请求，程序没有登记自动重试队列。`vector_status` 也返回当前优先级观察。此检查覆盖工具箱记录的受管任务及共享 Office 锁，不承诺检测所有外部 Office 操作。

关闭实验开关后，已有文件仍可读取，当前管理器持有的工作进程仍可取消。编译进程限制为单个任务、768 MiB 内存和 120 秒 CPU 时间，正常管理器还执行墙钟超时。

管理器异常退出后，项目工作台会显示导出状态的核对入口。只有原工作进程已退出、编译锁和项目锁可取得，且原请求、文档、回执和输出哈希一致时，所有者才能核对并恢复保存结果。成功导出只恢复到待检查，失败回执恢复为失败；原有审查与交付保留原值。没有有效回执时，可单独确认将本次导出标记为控制器中断，再由 Agent 使用新请求提交下一版。原输出、日志和调用记录继续保留。

核对恢复由界面的所有者接口 `vector.recover` 执行，Agent 的 `vector_status` 只读取恢复依据。程序不会重放编译、自动填写视觉审查，也不会结束旧 PID 对应的进程。进程存活或身份无法确认时，两种处理操作都会停止并显示依据。

编译器不接受 Python、原始 SVG、任意脚本或外部链接。背景属于画布设置，独立于用户绘制的矩形。`background=null` 保持透明；添加全画布白色矩形会改变实际内容。

## 文档格式 v1

所有未列出的字段都会报错，避免滤镜、阴影或其他效果被静默丢弃。单位为 `px`、`mm` 或 `pt`，所有坐标采用画布单位。`px` 按每英寸 96 像素换算物理尺寸。

| 层级 | 字段 | 要求 |
| --- | --- | --- |
| 文档 | `schema_version` | 必须为整数 `1` |
| 文档 | `mode` | 默认 `pure_vector`，受管请求要求纯矢量 |
| 文档 | `text_mode` | 默认 `editable`，受管提交须与签发选项一致 |
| 文档 | `canvas` | 必填，包含 `width`、`height`，可选 `unit`、`background` |
| 文档 | `objects` | 必填，对象数组，顺序为从后到前 |
| 文档 | `gradients` | 可选，线性渐变定义数组 |
| 对象通用 | `id` | 可选，唯一标识，首字符为英文字母或下划线，后续可含数字、点和连字符 |
| 对象通用 | `transform` | 可选，六个有限数值的非奇异矩阵 `[a,b,c,d,e,f]` |
| 对象通用 | `opacity` | 可选，范围 `0..1` |
| 图形与文字 | `fill` | 十六进制颜色、`none` 或 `{"gradient":"id"}`，默认黑色，直线默认无填充 |
| 图形与文字 | `stroke`、`stroke_width` | 纯色或 `none`，描边宽度为非负数 |
| 图形与文字 | `fill_rule` | `nonzero` 或 `evenodd` |

颜色支持 `#RGB`、`#RRGGBB` 和 `#RRGGBBAA`。分组只接受 `type`、`id`、`transform`、`opacity`、`children`，不接受继承填充。

| `type` | 必填字段 | 可选字段 |
| --- | --- | --- |
| `rect` | `x,y,width,height` | `rx`，圆角不能超过较短边的一半 |
| `ellipse` | `cx,cy,rx,ry` | 通用样式 |
| `line` | `x1,y1,x2,y2` | 通用样式 |
| `path` | `d` | 仅接受绝对或相对 `M L C Q Z` 命令 |
| `group` | `children` | 分组通用字段 |
| `text` | `x,y,text,font_family,font_size` | `font_weight` 为 `normal` 或 `bold`，`font_style` 为 `normal` 或 `italic`，`text_anchor` 为 `start`、`middle` 或 `end` |

文字对象接受单行 Unicode，不接受控制字符或换行。多行内容请拆成多个文字对象。`font_family` 填单个已安装字体族，不接受 CSS 字体回退列表。

每个渐变包含 `id`、`type="linear"`、`x1,y1,x2,y2` 和 `stops`。坐标采用当前对象的用户坐标系。每个 stop 只接受 `offset` 和 `color`，offset 在 `0..1` 内递增排列，允许相等。渐变端点不能重合。

## 带孔洞的透明画布示例

```json
{
  "schema_version": 1,
  "mode": "pure_vector",
  "text_mode": "editable",
  "canvas": {"width": 120, "height": 100, "unit": "px", "background": null},
  "objects": [
    {
      "type": "path",
      "id": "frame",
      "d": "M10 10 L110 10 L110 90 L10 90 Z M40 30 L80 30 L80 70 L40 70 Z",
      "fill": "#e03050",
      "fill_rule": "evenodd"
    }
  ]
}
```

外框内部的小矩形通过 `evenodd` 形成孔洞，不需要再用白色形状遮盖。原点和孔洞在 PNG 中都应保持透明。

渐变填充的最小扩展示例如下。将定义放入根节点的 `gradients` 数组，并给对应对象设置 `"fill":{"gradient":"ramp"}`。

```json
{
  "id": "ramp",
  "type": "linear",
  "x1": 0, "y1": 0, "x2": 120, "y2": 0,
  "stops": [
    {"offset": 0, "color": "#ff0000"},
    {"offset": 1, "color": "#0000ff00"}
  ]
}
```

## 编译器接口与限制

独立模块位于 `scripts/vector_document.py`。

```python
validate_document(document: dict) -> dict
compile_document(document: dict, output_dir: Path, formats: list[str]) -> dict
capabilities() -> dict
```

验证结果包含 `valid`、`errors`、`warnings` 和 `summary`。编译结果按格式保存 `status`；已生成文件包含绝对 `path`、字节数、`sha256` 和结构检查结果。`visual_review.status` 始终为 `not_reviewed`，PNG 路径列入 `visual_review.must_view_files`。受管服务另行记录查看后的审查意见。

`output_dir` 必须尚不存在，已有目录不会被覆盖。`formats` 必须为 `svg`、`png`、`pdf`、`ai`、`eps`、`psd` 的非空无重复子集。受管请求还要求选择至少一种文档输出格式，PNG 预览会自动附带。无效文档不会创建输出目录。

| 限制 | 上限 |
| --- | --- |
| JSON 输入 | 8 MiB |
| 单格式输出 | 64 MiB |
| 对象总数，含分组 | 5000 |
| 路径段总数 | 100000 |
| 嵌套层数 | 32 |
