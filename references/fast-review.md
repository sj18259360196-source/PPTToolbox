# 极速制作与验收

## 首版优先提交

新编号冻结 `delivery_policy.mode=first_complete` 并使用 `ppt-acceptance-trial/0.7` 时，首轮按本节执行。项目、页面与区域必须全部采用极速档位。缺少策略字段的历史项目，以及关闭开关的新项目，继续使用各自原合同。

保留拆分、位置标注、原图逐字转录和原生制作。整套页面完成后，查看当前候选经真实 Office 渲染生成的整页左右图，逐项核对标注清单、实际 PPT 结构和可见内容。`review_full` 使用 `completeness_checks`，每项记录当前对象编号、原图内容、Office 内容及缺项。只数对象或提交一句内容齐全不能通过。

位置、间距、字体相似度、颜色和装饰差异允许如实保留。首轮不默认生成叠图和局部对照，不要求箭头连接关系或组件内部编辑试验。素材来源和原生制作要求仍有效，整页图片不能代替原生文字、表格、图表与必要对象。

各页发现的缺项集中记录，只补漏字、漏图、漏页与不可见内容。无法辨认的项目保留 blocked，不能代填通过。控制器保留补漏前后的候选身份。首版取实际完整文件，与 run 目录编号无关。

完整性通过后调用 finish，交付文件字节必须与当前核对候选一致。随后 next、重复 finish 与重启都返回已有交付，等待用户反馈，不继续自动美化。未执行的外观、关系与编辑行为检查写明本轮不要求。

用户提出修改后，通过 revise 或 revision_candidate 登记具体意见，进入新的修改轮次。首版文件和原冻结合同保留，新的任务核对点名的改动。用户明确要求实际编辑、复建或叠图时，继续执行相应专项任务。下面的普通极速审查节奏适用于关闭开关与后续正常审查阶段。

纯极速合同 ppt-acceptance-trial/0.5 与0.6使用本页的集中复核节奏与轻微装饰容差。当前任务的 fast_review_policy.version 为 fast-structure-review/2。0.6另启用三档共用的文字标注协议，0.5保留原标注产物。已有编号使用其冻结合同，旧极速0.4保留原首检通过条件和外观门槛。标准版、精修版和混合档位项目保持各自检查深度。

## 按阶段登记

继续使用 start、next、submit、finish。当前任务的 schema 和输入文件决定本阶段工作，每次提交保存真实记录。自动阶段由控制器登记，不重复手工补登记。最终控制器允许交付后停止，不追加另一套自选验收。

## 先标注再制作

page_plan 登记区域、对象类型、制作方法、编辑能力、外观标准与风险。visual_criteria 按冻结的极速容差定义，覆盖准确内容、布局和关系，不把未被专项要求的轻微装饰差异列成精修义务。默认不填写替换文字测试样本。控制器生成一张多色框标注PNG和plan.json。

查看位置总览图，直接读取完整JSON，完成acceptance_plan_review。新0.6任务通过annotation_text.content内联完整文字，required_text_files保存文件及哈希；实际读过后按模板填写read_files，不重复读同字节文件。Markdown用于辅助核查，具体载体见[制作与交付要求](acceptance-guide.md)。不要将文字清单或前情说明转换成图片，不另生成文字型PDF。标注仅说明制作责任，不提前声称成品通过。

## 制作与外观

优先批量制作、复用合格素材和样式。保留原文、数字、布局、识别轮廓、孔洞与语义关系。整体清楚、内容及布局正确且没有用户专项要求时，轻微字体、颜色、圆角和柔和阴影差异可如实记录并接受。不要为这些差异反复返修，也不漏建原图内容。

指定字体、精细字体设置、准确色值或已明确的轮廓要求继续有效。来源、素材授权和编辑范围保持原约束，不能用极速容差替代这些要求。

首轮集中查看正式 Office 整页左右图与叠图，一次列齐明显问题，再合并修复。真实查看叠图的事实与整页是否通过分开保存，首轮有缺陷不导致后续每版继续叠图。LibreOffice 预审不完成正式首检。

默认完成一轮集中修复和受影响复核。需要放大时，只看受影响位置的局部左右图，再快速确认整页没有新溢出、遮挡或布局问题。控制器下发的必要局部仍须查看，以左右大分区承载，不逐组件生成对照。全页已能判断且无局部义务时，不增加局部任务。

规划不泛加 local_review。已下发的必查对象仍由必要左右大分区覆盖，不能凭整页可读跳过当前局部任务。review_full 提供 review_bundle 时，一次看完所列必要图片，再按当前模板用 additional_reviews 集中提交各局部的真实观察，避免同一版本多次领图。未变局部仅按控制器认可的证据复用，不自行撤销检查。

后续默认不再叠图。大幅布局变化、显式精确要求或频繁叠图设置触发时，按当前任务的 overlay_check 与 must_view_files 执行。普通局部修订和整页计划更新不自行恢复全页叠图义务，具体触发以控制器判断为准。

文字或数字错漏、关系及箭头错误、明显偏位、溢出遮挡、来源缺口与编辑结构错误继续阻断交付。只为阻断缺陷继续返修，不开启新的装饰试验。达到修订轮数不会自动通过。未变输入复用有效证据，不重复执行已接受任务或结果未知的 Office 写入。

## 编辑能力

控制器对最终PPTX执行native_structure审计，逐对象核对实际类型、文字和表格内容、图表关系及数据、组成员、图片资源。审计绑定当前候选文件，不能用计划中的声明代替。

默认不执行改字、移动、缩放、换图、不同底色、编辑后视觉测试或独立复建。用户明确要求实际编辑或复建时，控制器恢复相应专项检查。

原生文字可修改文字内容。独立图片支持整体移动、缩放、裁剪和替换，图片内部文字与像素不因此成为独立原生对象。需要独立替换的照片应拆成独立图片对象。

结构检查通过只证明报告覆盖的结构能力。未执行实际编辑时保留behavior_executed=false，不填写实际编辑已通过。结构错误、来源缺口及超出冻结容差的外观缺陷继续阻断交付。
