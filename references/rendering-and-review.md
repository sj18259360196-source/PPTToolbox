# 渲染、审查与交付

## 审查顺序

先原文和关系，再轮廓与几何，随后文字、素材边缘、渐变和装饰。全页用于版式与阅读顺序，局部用于箭头端点、微小文字、下标、孔洞和裁切。E19局部检查开展偏晚，E21用户指出半圆轮廓，故关键局部应从首版开始检查。

同一裁切框和同一缩放倍率比较。把左右图缩小只能完成整页检查；不得不同缩放或加模糊来掩盖偏差。每轮大改后重新导出，同名旧图不能当新证据。

## 任务提交状态

`rebuild_submit` 的审查状态只接受 `passed`、`needs_changes`、`blocked`。发现需要修改的问题使用 `needs_changes`，不使用 `failed`。当前任务的 `submission_constraints` 和响应模板给出适用字段。

每项观察写出具体对象、位置和差异。未查看的图片不填写为已查看，明显缺陷尚未解决时不填 `passed`。

## 汇总报告状态

汇总报告中的 passed 表示执行且达到该项要求；failed 表示执行后发现不符合；blocked 表示依赖、能力或证据不足；not_run 表示未执行；not_applicable 表示无适用对象。控制器把任务的 needs_changes 转为报告的 failed，并计算不适用项。Agent 不把这些报告枚举直接填入任务提交。

没有Chart的页，图表检查是not_applicable而非证明图表功能通过。没有有效数值列的算术验证不等于数值验算。硬编码的full_slide_reference_image=false、powerpoint_rendered=true不能视为自动检测。来源E05/E06/E16。

## 六类验收

| 维度 | 检查内容 | 本包自动覆盖 | 仍需Agent/实际软件检查 |
|---|---|---|---|
| 内容 | 文字、数值、单位、行列 | scene与PPT文字/表格对应 | 截图→scene是否正确、强调和模糊字 |
| 关系 | 起止节点、方向、分支 | 存在性与部分连接数据 | 语义、遮挡、双向端点 |
| 编辑性 | 文本、形状、表格、数据图表 | 对象类型和基本数据缓存 | 副本中实际修改、保存、重开 |
| 视觉 | 边界、字形、间距、轮廓、边缘 | 对照图片、MAE | 全页和关键局部判断 |
| 文件 | ZIP、XML、关系、目标软件 | CRC、XML语法、内部目标、Office收据 | 完整Schema、跨设备兼容 |
| 交付 | 文件与证据同版本 | SHA256、图片完整、审查覆盖 | 源脚本重跑、用户确认状态 |

## 实际修改抽查

在副本上修改每页至少一个文本、一个代表性形状填充，含表格时改一个单元格，含数据图表时改一个数据点并看更新。保存、重开、导出，再确认效果。不要在最终已认可版本上试验。

样例抽查不能证明所有对象都同等可编辑。图标内部路径、附加轴标签、公式分数线和表格附加网格需按用户关键需求专门抽查。把范围和未覆盖项写明。

重复卡片和多对象贴纸需要整体移动时，补查分组及保存重开后的成员位置。同文叠字模拟描边时，专门修改花字排除残留。可用 `pptx.editing-structure` 和 `office.group-roundtrip`，见[视觉保真与编辑分组](visual-editing-repair.md)。允许近似不豁免识别轮廓与用户明确指出的缺陷；关键局部看完后再确定整页通过结论。

## 文字与几何

读取真实文本框和可见字形范围。旋转、组内对象、艺术字和表格用独立方式检查，不能把不适用项跳过后写全通过。矩形包围框相交可能是预期布局；要定位对象并保存接受理由。

inspector只自动判断未旋转根级对象的画布范围，容差0.5pt。组内变换和旋转列入deferred；它不检查所有可见阴影，也不做全对全碰撞判断。

## 扩展画布检查

历史多份记录用扩展画布、灰色外边和像素检查发现越界。扩大PowerPoint页面时可能自动移动内容，必须先存原几何、修改尺寸后按原坐标＋边距恢复，不能额外再移一次。测试副本的背景也要覆盖原画布，外边才使用灰色。

本包没有实现通用扩展画布渲染器。若当前宿主有可用slides_test，先核对其真实路径与接口，再调用；失败保留原结果。不能把本包的普通几何检查改名为历史slides_test已通过。

## 截图扁平化检查

联合查看媒体实际内容、图片显示范围、素材角色以及文字/结构原生覆盖。检测原文件哈希只能排除原样嵌入，不能排除重新编码、缩放或拼块。

大幅清洁照片可以合法作为背景，所以大图提示只是待审项；小图也可能包含成块正文。以正文、表格、主要卡片与关系是否独立为核心，不只限制图片面积。

## 对照指标

compare_images生成同尺寸左右、50%叠加与绝对差，报告原始RGB MAE和1-MAE/255。分辨率不同时默认报错；显式resize会记录实际变化，不隐式拉伸。

不设置通用95%阈值，不把像素接近度命名为已认证还原率。大片浅色背景可掩盖一个错字或缺失箭头。E22的95%分区工作阈值是当次约定，不能默认推广。

## 审查记录

review.template.json含8个独立检查项，初始均not_run。记录reviewer、最终PPTX/scene/对照收据哈希、已看页、检查说明、证据文件及SHA256。content_source、visual_full、raster_scope、text_geometry要覆盖所有页；editable_behavior记录实际抽查范围。

几何告警接受理由写入text_geometry；有关图表的未支持缓存项不能默认为通过。用户认可单列user_acceptance，不因Agent完成修订就自动填passed。

verify_delivery只验证证据身份和声明覆盖，无法证明审查者真的看图。篡改收据或把模板批量填passed仍属于虚假验收，不是有效用法。

## 结束

通过任务必需项后固定版本。关键内容未确认、目标Office未验证或用户明确提出的问题未解决时，只能交付待验收候选并列出差异。完成用户确认后停止新的装饰试验。

交付可编辑范围说明、未确认项、已执行/未执行检查以及最终文件和对应预览。重跑构建需使用持久输入与明确步骤，不执行所有试验脚本来猜顺序。

## v1.1 强制左右对照门禁

只要任务属于参考稿复刻，每页都必须有参考图与PowerPoint成片的全页左右对照。以下任一情况成立，视觉审查不得标记为passed：

- 没有`deck-comparison.json`。
- 某页没有`full-side-by-side.png`。
- 对照图不是由最终PPTX对应的PowerPoint导出图生成。
- 左右图尺寸不一致，却没有明确记录resize。
- 只看overlay/差异图，没有看左右原图与成片。

推荐命令：

```powershell
python scripts/compare_deck.py scene.json `
  --pptx run/candidate.pptx `
  --render run/office/office-render.json `
  --outdir run/comparisons `
  --regions evidence/review-regions.json
```

单页调试：

```powershell
python scripts/compare_images.py input/slide-001.png run/office/slide-001.png `
  --outdir run/compare-001 --regions evidence/slide-001-regions.json --region-scale 2
```

### 复杂页必须有局部对照

存在下列对象时必须按实际对象ID覆盖局部审查区；不允许只给整个复杂页随意放一张局部图：

- 异形图或布尔轮廓
- 复杂图标或生成素材
- 双向/反馈箭头
- 环带、三角关系、流程逻辑
- 密集表格、图表、公式
- 用户明确指出返修的区域

局部对照只放大显示，不改变比较裁切框。两个版本必须使用相同的`bbox`。局部图如果发现轮廓错误，先修轮廓，不允许用颜色、阴影或模糊把错误结构“美化过去”。

### Agent必须实际看图

自动生成对照文件只说明证据存在。Agent还要查看最新`*-side-by-side.png`，并在review的`visual_full`/`visual_local`中写清：

- 哪些页/区域已看
- 观察到的主要偏差
- 本轮修正了什么
- 哪些差异被接受及原因

没有这些说明，`verify_delivery.py`即使能核对文件身份，也不能证明视觉验收完成。

## v1.1.1 证据关联与必查覆盖

当前原图/参考清单、scene、PPTX、Office收据及逐页PNG、逐页comparison、全部全页/局部图都参与检查。`verify_delivery --scene ...`不能省略。review必须绑定当前scene和对照收据。

`visual_local.regions`逐区记录对象ID和观察，证据必须指向该局部左右图；`relationships.objects`逐连接记录两端、方向和观察。应查对象由scene推导，加上用户明确指定项；声明不适用不能清空应查集合。原图中完全漏建的东西仍需要源图审查发现。

区域ID、裁切、对象覆盖及旧项目升级方式以[第一阶段修复说明](phase1-fixes.md)为准。所有图像收据仍然只是可核查记录，不是宿主工具执行的密码学证明。

### 原文逐项核对

`source_review` 可提交非空 `text_checks` 数组。每项填写当前文本对象的 `object_id`，以及从原图独立读出的完整 `source_text`。程序按字符比较文本、富文本片段及段落内容，保留标点、空格、数字和单位差异。段落之间使用换行符。

存在差异时不能提交 `passed`，应提交 `needs_changes` 或 `blocked`，再返修对应对象。重复编号、失效编号和非文本对象编号会被拒绝。核对结果随本次复核记录保留。

这些记录只覆盖列出的文本对象。表格、遗漏内容、关系和未列出的文字仍需查看原图。不要复制候选文字充当原文；程序无法判断复核者是否正确读懂原图。

### 普通区域返修的历史图

普通区域通过 `workflow.revise` 重开后，下一次 `region_objects` 任务在 `revision_feedback` 中提供返修原因。上一版对象与当前已渲染场景一致，且场景、PPTX、Office 回执、图片和对照记录校验通过时，任务还会附上同一裁切框的旧局部图及相关旧审查意见。旧图会列入必看文件。

旧局部图包含上一版整页的上下文。对象改过但尚未重新渲染，或历史文件缺失、改动、身份不符时，任务注明历史图不可用，不从更早版本猜选图片。整页重新规划会清除这些区域记录。导入场景的区域恢复仍走原有恢复流程。

旧图和旧意见用于定位偏差，旧审查状态不会成为新版本的验收结果。修改后仍须重新核对源图文字、生成候选、导出 Office 图片并完成审查。回执校验也不构成对实际宿主执行的独立证明。

### 保留未改对象的返修

有上一版区域数据时，`region_objects` 任务会提供 `previous_fragment_sha256` 和 `object_revision` 约束。局部修改可以提交 `action: "revise_objects"`、该摘要、修改原因 `reason`，以及 `objects` 或 `components` 替换列表。每项必须是完整的替换记录，使用已有的顶层局部编号；省略的记录由程序原样保留。

这条路径保留原来的顶层顺序、源图说明、关系声明、素材决策和不确定项。修改原因单独保存在本次响应记录中。修改组内对象时，需要替换整个父组。需要增加或删除顶层对象、调整顺序或改变素材路线时，仍提交完整区域数据。

摘要过期、编号不存在或重复、替换列表为空、没有实际变化、合并后的几何无效都会被拒绝。程序会校验合并后的整个区域，随后重新进行源图核对、构建和审查。减少输出量并不降低验收要求。
