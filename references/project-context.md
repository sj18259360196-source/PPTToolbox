# 项目目录与上下文

工具箱使用两个稳定位置。`storage.toolbox_root` 保存已安装程序、Skill 和工具；`storage.management_root` 保存全局配置、管理日志、工具缓存、实例状态和项目登记。安装包代码与可写管理数据分开放置，升级和切换 PPT 项目都不改变管理实例。所有工具入口来自当前实例，不使用项目文件夹查找工具。

`settings.projects_directory` 只是默认项目根目录。未设置时使用 `C:/Work/PPTProjects`，用户可以在设置中点击浏览更换。它不构成可读目录白名单，也不限制盘符。用户没有指定目录时，在默认根目录下建立日期加主题命名的独立项目文件夹；用户明确指定的目录直接成为本次 `project_root`。已有授权规则继续按具体项目和输入目录生效。

| 项目相对位置 | 用途 |
| --- | --- |
| input | 原始参考图与输入记录 |
| assets | 本项目素材和出处 |
| runs/run-* | 每轮制作、预览、对比与审查 |
| workflow | 当前状态、任务、提交记录和修改历史 |
| logs/tool-calls/调用ID | 本项目调用输出、错误及执行记录 |
| delivery/run-* | 对应版本的可编辑 PPT、制作依据和交付记录 |
| HANDOFF.md | 续作摘要 |

先调用 `toolbox_project_bind`。传 `project` 使用用户指定的完整目录；传 `name` 在默认根目录下选择一个尚不存在的任务目录。绑定只建立本 Agent 会话的上下文，不创建文件、不修改全局设置，也不自动授权。

返回值包含 `context_id`、`project_root`、`project_id`、`paths`、`current_pptx`、`current_scene`、`current_run` 和 `current_delivery`。后续 `rebuild_*` 调用携带 `context_id`，可省略 project。每次调用重新检查项目身份并从当前状态解析路径。切换项目时重新绑定，旧 context_id 立即失效；另一个 Agent 会话保持自己的绑定。重连后重新绑定明确目录，不扫描默认根目录猜测项目。

明确指定的已有工作区可以原地初始化，保留用户已有文件。工具先在工作区内临时准备，再发布未占用的标准目录，最后发布 workflow。已有标准目录发生冲突时停止初始化并保留内容；已有 workflow 使用 status/next 续作。中断留下的初始化锁需核对实际状态，不自动删除或重试。

项目记录使用项目相对路径。移动整个项目后，以新目录重新绑定并核对已有项目 ID；旧上下文会拒绝继续使用。路径授权仍需覆盖新目录。成功调用后，如果旧位置已不存在，项目登记更新到当前路径并保留路径历史；原调用日志保持原样。

受管 CLI 每次明确传项目路径。工作流使用原有 `--project`；其他项目工具在工具参数前加 `--project <完整目录> --`，相对输入输出据此解析。全局诊断和工具管理无须绑定项目。Python、PowerShell 和工具资源从稳定工具箱位置加载。

全局 SQLite 保留管理操作与调用审计索引。项目调用的 stdout、stderr、代码版本记录及 call.json 放在本项目日志目录。新项目尚未建立时，启动调用临时写入工具箱 cache，成功建立后归入项目；启动失败或超时保留明确的诊断路径。原有历史日志保持原样。

交付使用当前项目的 `delivery/<run_id>`，不复制到全局 output。再次修改产生新的制作版本，旧交付继续与素材、修改记录关联。目录测试证明文件归属和调用隔离，不代表 Office 或视觉还原通过。
