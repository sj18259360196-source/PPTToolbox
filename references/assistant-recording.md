# 助手自动记录与补图

制作 Agent 正常使用制作工具并保留必要的大阶段打卡。工作图不要求逐项登记，PPTAgent 从本项目已有调用中集中整理。详细路线为默认视图，五个大阶段保留在制作记录中。

启用 Responses 助手后，软件按项目读取连续事件，每批最多 32 条，单次查询最多 160 条。批次还包含已有工作图、最近阶段记录和当前任务。常规一批使用一次模型请求，同时返回节点说明、关系建议、摘要和管理备注。Chat Completions 兼容模式继续只整理摘要。

最小间隔、小时与日请求上限沿用设置。后台可在有新调用时排队，重启后从已保存游标续接。自身写入摘要、备注和图不会触发下一次模型请求。若事件仍有积压，等待间隔后处理下一批。

打开项目、新的工具活动或已有整理任务可以触发处理。升级与重启不会仅因轮询旧项目目录，就把所有历史项目重新送入模型；已归档项目不自动整理。

## 内置接口

这些接口供工具箱内的 PPTAgent 使用。制作 MCP 的工具数量保持不变，不要求制作 Agent 学习一组新的记录指令。

| 接口 | 输入 | 返回与用途 |
| --- | --- | --- |
| read_production_status | project | 当前工作流版本、任务、阶段、最近调用和观测限制 |
| read_project_activity | project、cursor、limit | 连续事件、next_cursor、has_more，按项目隔离 |
| describe_project_tools | project、query | 已登记工具用途和输入说明，图形工具附参数结构；不授予执行权限 |
| read_work_graph | project | 图、graph_revision、整理状态和节点结构 |
| prepare_project_batch | project | 不可变 batch_id、事件、软件建立的节点和更新合同 |
| preview_work_graph_update | project、batch_id、update_json | 只校验并预览，不保存；更新包含 summary、note、patches |
| commit_project_update | 同上 | 一次保存图、摘要、备注与游标，重复提交不重复写入 |
| read_work_graph_history | project、before | 每页最多 20 个版本；before=0 为最近版本 |
| restore_work_graph | project、history_id、graph_revision | 恢复选定历史图为新版本，保留制作工作流和处理游标 |

已有 update_work_graph 保留，人工或管理任务修改同样增加图版本并保存历史。批次补图只能编辑实际观测到的节点或已有助手节点，不可改动制作 Agent 登记的节点。图同时被修改时，旧批次拒绝覆盖，需要重新准备。普通文件变化或制作工作流继续推进不使整批失效。

## 执行状态与图关系

软件依据调用事件、观察器状态和匹配的持久回执确定节点状态。模型不能把未知结果改为完成，不能伪造任务、工具或证据编号。同一次调用使用稳定节点编号，开始和结束不会各画一个节点；不同尝试保留各自记录。

软件按任务编号与可核对的返修记录维护归属。同任务调用可补充有记录依据的先后箭头，箭头明确说明调用先后不等于执行依赖。执行重叠或上一调用结果未知时，不强行串行。无法判断归属时进入关系待确认分组，旧节点缺少时间依据时保留轮次待确认。

模型补充的关系保留 inferred 或 suggested 标记，并校验引用归属及循环。fork 表示明确登记或推断的并行分支，merge 表示汇合，join_policy 说明 all、any 或 unspecified 条件。分组表示任务层级，grouping 归属从执行排序中移除。同一列不表示并行。调用完成显示为调用已完成，不表示视觉验收通过。

read_work_graph 同时返回原始图、展示节点、lifecycle 与关系诊断。prepare_project_batch 包含轮次、任务分组与交付记录，软件提供这些字段，模型不覆盖。preview_work_graph_update 和 commit_project_update 继续一次处理本批更新；无需增加制作 Agent 的逐工具登记。

工作流每次明确返修创建后续轮次，交付按输出版本保存。交付后显示等待展示或用户反馈，只有对应版本的确认记录才显示已记录认可。后续修改连接到新轮次，保留旧版本，图保持无环。未登记的宿主用户聊天不可见，不能推定用户认可或把检查返修解释为用户要求。

实线表示记录或明确登记的关系，虚线只表示推断或建议。跳过与替换使用节点状态，选中节点时其他连线仍可辨认。界面最多展示 128 个节点，其中原始工作图仍最多 64 个节点，额外节点只用于交付与反馈投影，不写回制作状态。

自动任务逐项检查模型建议。抄错编号、倒置先后关系或其他不合格建议单独保留诊断，不采用到图中，也不为它们再次请求模型；真实调用节点、合格建议、摘要和备注仍按同一批保存。版本历史列明未采用的建议。直接调用预检和提交接口仍采用严格校验。

当前展示图最多 64 个节点。超出时把旧的助手终态节点存入该版本历史，保留原事件；正在执行和结果未知的节点优先保留。人工登记节点不自动删除。无法在限制内容纳时停止本批，显示待检查。

## 失败、恢复与可见性

整理失败不推进游标，采用延长间隔的重试。同一连续失败链达到三次后暂停，由用户检查后重试。请求配额用尽时等待窗口恢复，不额外消耗模型请求。关闭助手或修改模型配置时，旧请求的结果不能继续落图。

项目页显示累计整理事件数、当前图版本、上次保存时间和是否还有记录。失败信息位于助手区域，制作问题继续单独显示。图版本历史可查看并恢复；恢复只改变展示图，不回退 PPT、制作任务或审计日志。

助手只了解工具箱中可观察的活动。它无法读取制作模型的内部思考、宿主中未登记的操作或外部软件中的编辑。输出质量仍取决于实际证据和所配置模型；模型不可用时，本地采集继续运行。
