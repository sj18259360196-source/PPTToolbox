# 项目目录与 Agent 操作合同

受管项目以当前 toolbox_context 的 project_context 为准。directory_contract 提供用途和路径，references 提供已登记原图与读取问题。不要根据目录里的图片数量推断页数。

受管导入、裁切、透明处理和背景预览会在 evidence/provenance 保存来源、参数与文件哈希。工作流提交时把登记记录、已接受素材、冻结输入和构建证据写入 state 的 artifact_registry，后续读取核对已接受来源记录的哈希。外部来源只记录导入时观察到的身份，不要求原外部文件一直存在。

`toolbox_project_inspect action=layout` 的 delivery_preflight 列出当前依赖缺失、内容变化、缺失证据和临时文件建议。依赖沿已登记来源递归检查；存在临时依赖或检查超过上限会阻止交付。cleanup_candidates 仅供核对文件归属与活动进程，工具不会删除文件。通过此检查后仍须完成原有 Office、视觉和编辑门禁。旧项目只读检查不会补写登记记录；后续受管写入才登记现有状态可证明的依赖。

| 位置 | 用途 | 操作规则 |
|---|---|---|
| input | 原始输入及 references.json | 保留原图，通过明确的参考图更新流程更换 |
| assets/crops | 参考局部裁剪 | 保存来源路径与裁剪范围 |
| assets/generated | 生成素材 | 保留真实生成记录和来源 |
| assets/imported | 导入素材 | 保留来源及许可信息 |
| assets/native | 原生绘制素材与生成脚本 | 保留重建依赖，避免系统临时路径 |
| runs | 受管候选版本 | 工作流分配，不覆盖旧轮次 |
| workflow | 状态、任务与续作记录 | 使用受管接口维护 |
| evidence | 跨步骤验证证据 | 关联具体对象与版本；运行内证据留在原版本 |
| delivery | 正式交付包 | 使用交付流程维护 |
| logs/tool-calls | 调用日志 | 与素材分开 |
| .tmp/codex/任务名称 | 本任务临时文件 | 检查依赖后清理本任务文件 |

旧项目的 build 继续保留。受管工作流的新候选统一使用 runs。读取、检查和升级不自动移动旧文件。

## Agent 开始与续作

先读取当前实例和项目上下文，核对路径、身份与未决操作。已有状态通过 rebuild_status 续作，新建项目通过 rebuild_start 初始化。不要手写 workflow/state.json。

按已登记顺序看完整原图，再填写 page_plan。notes 简述制作优先级、素材来源、预期输出和验证方式。区域保留内容归属、编辑需求与层级，简单对象不增加重复规划。

裁剪、生图和导入素材使用 assets 下对应目录。现有 assets 根级文件继续可用。构建前核对显式素材依赖，返修后重新渲染对应版本。结束前保存当前候选、未完成项与续作入口，检查临时文件是否仍被正式场景或脚本依赖。

## 只读检查

通过 toolbox_tools 查找 project.layout.audit，再通过当前管理器的受管 execute 调用。工具参数为 --project 后接已授权项目绝对路径。项目界面 API 的 project.layout 读取同一检查结果。

检查登记原图、校验值、未登记输入图片、旧 build 目录和当前场景显式素材依赖。结果附问题代码、文件路径及严重程度。检查不执行脚本，不补写视觉验收，也不推断脚本的动态依赖。

整理旧项目时先根据检查结果列出具体文件及引用更新方案。明确确定素材用途后再执行移动，原图和不确定文件保留。清理继续经过已有预览、锁和依赖保护，不依据目录名直接删除。
