# 管理器结构与迭代边界

## 模块

```text
manager.py                      启动、上下文、检查、注册、受管执行
  toolbox_manager/
    storage.py                  SQLite配置、修订和审计
    packages.py                 ZIP预检查与离线包清单
    service.py                  单一管理服务与入口级策略
    integrations.py             本机Skill/MCP/市场配置生成
    server.py                   127.0.0.1与会话认证的HTTP适配
    mcp.py                      stdio管理发现（只读）
    web/                        本地前端，无外部CDN或构建依赖
  toolbox.py + scripts/         原v1.3.0制作、检查、评测核心
```

UI不维护独立的工具或版本状态。UI、CLI、MCP均调用service与同一个SQLite数据库。制作核心保留，不在管理器里重新实现原生形状、图表或审查逻辑。

## 稳定接口

管理API版本 `ppt-toolbox-manager/1`，数据库schema_version为1。启动发现未知数据库版本时停止，不能把新结构覆盖为旧结构。

工具目录来自每个包的toolbox/registry.json。当前格式与既有v1.2注册结构兼容。捆绑核心保留72项；管理器额外暴露14项根工作流入口。所有入口明确区分可执行脚本、PowerShell模块、宿主能力和手册。

扩展新的可执行能力时需要真实entry、输入说明、输出说明、使用限制、手册路径及测试。纯说明条目不能变成可执行能力。注册条目不会自动执行；导入默认不信任。

## 包与版本

随包核心只读，导入版本存入管理数据目录packages。活动指针在SQLite中；切换不覆盖旧目录。用户指令覆盖按包ID与文档路径保存，保留乐观版本校验与修订历史。

版本不是只靠版本号判断：同号不同内容以内容指纹区分。激活前重新检查导入后的文件内容。MANIFEST可验证完整性，但不能认证发布者；下一步可在明确签名信任模型后增加签名验证，不能把现在的哈希称作签名。

浏览器先检查包再确认导入。代码、钩子、依赖不会在导入动作中执行。工具运行只在显式信任、启用且允许受管执行后发生。

## 用户设置

制作项目独立于程序和管理数据库。UI更新不要求移动PPT项目。设置与文档写入使用乐观revision检查；冲突返回错误，不以最后写入强行覆盖。

主题和日志条数立即影响UI；Python/PowerShell路径用于实际诊断与受管执行；host_generation_allowed只作为给Agent的偏好，不冒充宿主权限；network_benchmarks_enabled阻断或开放受管bench.run入口，原预算与授权流程仍保留。

## 后续迭代建议

可逐步增加签名的发布源、配置迁移、指令跨版本三方合并、可选桌面壳和宿主安装状态读取。当前不伪造这些功能按钮。

MCP仅提供管理发现，未实现任意命令调用。后续要暴露写入或执行工具，应逐工具定义参数、审批和能力范围，不能加一个无限制shell工具代替。

UI通过普通函数分区组织，现有静态模块不要求Node。页面复杂度增长后可以替换前端框架，管理服务与数据协议不随之重写。
