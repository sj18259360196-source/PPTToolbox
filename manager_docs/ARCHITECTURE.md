# 管理器结构与迭代边界

## 桌面与服务

Windows 桌面使用 `desktop/` 中的 Electron 宿主，加载原有业务界面并启动随包 Python 服务。`manager.py` 提供 CLI 入口，`toolbox_manager/mcp.py` 提供 stdio MCP，`server.py` 提供本机 HTTP 适配。界面、CLI 与 MCP 共用管理服务、SQLite 和实例位置配置。

`storage.py` 保存配置、修订和审计，`packages.py` 检查工具包，`integrations.py` 处理 Agent 接入。`toolbox.py` 与 `scripts/` 保留制作、检查和评测核心，管理界面不另行实现 PowerPoint 对象操作。

## 受管接口

管理 API 使用 `ppt-toolbox-manager/1`，数据库 schema_version 为 1。遇到未知数据库版本时停止，避免用旧结构覆盖新数据。

MCP 同时提供上下文发现、项目绑定、设置、受管制作、审查与管理工具。它包含写入和执行能力，调用仍需符合对应项目授权、执行开关与工具策略。实际工具数量及参数以当前工具枚举、registry 和 describe 返回为准。

扩展能力应提供真实入口、输入输出、限制、手册与测试。说明条目不能冒充可执行工具，注册与导入不会自动执行。CLI 使用明确 argv，受管接口不提供无限制 shell。

## 包、更新与数据

随包核心通过安装包更新，独立扩展保存于管理数据目录的 packages。用户覆盖按包与文档路径保存，保留修订和冲突检查。内容指纹区分同号不同内容，导入前后检查完整性。

软件更新清单使用 Ed25519 签名，安装包核对 SHA-256。工具包 MANIFEST 的哈希只说明内容完整性，不能认证发布者。软件更新与 ZIP 扩展导入遵循各自流程。

制作项目独立于程序和管理数据。新安装默认项目目录为用户文档目录下的 `PPTToolbox\Projects`，升级保留用户选择。项目设置按项目保存，提示词草稿与编号由 `prompt_projects.py` 管理；全局默认变化不会覆盖已有项目。详见[制作设置](../references/production-settings.md)。

独立矢量项目使用自己的请求、候选、检查与交付记录，通过统一项目目录参与列表和管理。项目内运行路径由已保存记录投影，按所选候选隔离版本；全项目当前服务与助手状态另列。管理摘要和备注使用独立记录，不写入矢量执行状态，也不进入 PPT 工作流。操作与格式范围见[矢量项目使用说明](VECTOR_SPACE.md)。
