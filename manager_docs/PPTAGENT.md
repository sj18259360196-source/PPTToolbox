# PPTAgent 接入与管理

工具箱内的 PPTAgent 使用 Responses API。Codex 等制作 Agent 通过另一套 MCP 连接负责制作与阶段打卡，配置入口在设置中的制作 Agent 接入。

左侧打开 Agent 接入，填写完整 Responses API 地址、模型名称和 API Key，保存后点击测试连接。测试会验证一次工具调用及结果回传，不读取项目内容。Key 使用 Windows DPAPI 加密保存在本机，界面不会回显。

启用后，项目变化会触发后台摘要。管理助手接受简短任务，可选择一个项目，也可查询全部已登记项目。管理任务会显示等待、处理和结束状态，以及实际调用过的工具。空闲时不轮询模型。

使用 `gpt-6.1-sol` 时，软件自动采用较低推理强度处理这些短任务，无需增加配置项。接口偶发超时或服务错误仍会显示为失败，已执行的操作不会自动重放。

## 管理功能

| 工具 | 范围 |
| --- | --- |
| 查询项目 | 读取已登记文字索引，不扫描全部目录 |
| 读取项目记录 | 阶段、实际调用、文件索引和管理备注 |
| 检索经验 | 每次最多三条相关经验 |
| 查询待办申请 | 读取待授权申请与已有自动审批设置 |
| 按授权规则处理申请 | 只应用已有授权或用户已开启的自动审批规则 |
| 保存管理备注 | 仅限界面选定项目，先检查记录版本 |
| 更新工作图 | 仅限所选项目，增量整理步骤、状态和前后关系，不推进制作阶段 |

管理备注与用户说明分别保存，不覆盖制作阶段、打卡和交付状态。PPTAgent 无终端或任意文件写入工具，不修改 PPT。审批通过不会自动执行制作任务，也不会开启被关闭的执行权限。明确拒绝或已归档的申请保持原状态。批量归档、交付和手动排序由用户在项目页操作，管理助手不提供这些批量操作。

## 处理记录

每个任务最多四轮模型请求、八次工具调用。网络请求在后台运行，不占用界面的写入锁。取消会停止后续工具调用；已经执行的操作保留在记录中。配置改变后，旧任务不再继续执行。中断任务在重启后显示中断，不自动重放。

最近二十条管理任务保存在本机管理数据库，Agent 接入页展示最近八条，工具调用同时记入运行日志。使用统计页记录制作工具和资源使用，PPTAgent 处理记录在本页查看；模型 Token 和费用以 API 服务商账单为准。项目管理备注保存在项目的结构化事件记录内。程序读取权限和项目范围由工具校验，模型不能自行修改。

## 数据与兼容

模型会接收管理任务、相关项目记录和工具返回结果。默认发送 `store: false`，多轮工具调用由本机传回必要上下文；这不替代服务商自己的日志和数据保留政策。PPT 正文与参考图片不会由这些管理工具上传。

已有 Chat Completions 配置继续用于辅助摘要。管理工具和连接测试需要 Responses API，可在兼容设置中选择。更换协议时也要填写对应的完整接口地址。

更换地址、模型或 Key 后重新测试连接，查看本次工具调用和返回结果。开启后按项目变化整理摘要，空闲时不请求模型；最近一次成功状态保留时间供核对。

## 更新项目工作图

驻留助手增加 update_work_graph 工具。先选择项目并读取记录，再提交步骤变化；软件自动排布方框与连接线。更新只影响展示记录，不能代替制作 Agent 打卡或批准交付。调用格式见[工作图说明](../references/project-work-graph.md)。
