# 使用统计

在左侧打开使用统计，可按最近 7 天、最近 30 天或全部时间筛选。经验、工具、图标和组件技能旁边的次数链接会打开对应明细。明细保留时间、项目、任务、入口、结果和记录依据。统计页刷新不会增加使用次数。

| 对象 | 计数口径 |
| --- | --- |
| 经验 | 检索和阶段推荐按条目记录；打开详情、原文分别计数；制作 Agent 在阶段打卡的 used_experiences 中登记实际采用 |
| 工具 | 记录受管入口的调用、成功、失败、等待及未知结果；策略拦截单列；耗时来自已有调用日志 |
| 图标 | 查看、提取片段、加入项目素材分别计数；最终场景保留版本归属且交付文件摘要核对通过，才记录交付保留 |
| 组件技能 | 应用失败记录尝试；生成试用样件记录应用；已有应用验证结果通过后记录交付保留 |

结果栏记录单次工具执行的成功、失败或等待状态，项目交付状态在项目页查看。经验采用记录保留 Agent 报告的用途，图标和组件的交付保留依据已有交付凭据。直接运行未接入管理器的脚本、手工复制和外部软件操作不进入自动计数。

归档只改变项目列表的显示范围，历史使用记录继续计入所选时间段。PPTAgent 的管理任务和工具步骤在 Agent 接入页的最近处理中查看，模型 Token 和费用在 API 服务商处核对。

统计存放在当前管理数据目录的 `usage/usage.sqlite3`，独立于安装程序。应用升级继续使用原管理数据。调用编号、应用编号、任务编号和界面事件编号用于去重；同一事件重试不会重复增加。

首次打开时按已有审计日志回填工具记录。旧日志没有标记的测试可能仍包含在历史累计中，明细会保留分类依据。历史经验查看次数无法补回，从启用统计后记录；缺少时间的组件历史只进入全部时间。暂无记录不代表从未使用。

验证进程设置 `PPT_USAGE_TEST=1` 时，新记录标记为测试；项目路径包含 `.tmp`、`checks`、`pytest` 或 `fixtures` 目录也按测试处理。默认隐藏测试，可勾选包含测试记录查看。状态轮询、经验审计和工具帮助等维护调用不进入使用次数。

新工作链优先在已有阶段打卡中填写 `used_experiences`，只记录实际采用的经验编号。软件将阶段推荐计为检索返回，将采用计为任务引用，并保存阶段、项目和打卡编号。相同 `checkpoint_id` 的重试会去重，无需再额外调用引用工具。

旧任务或需要绑定具体对象时，仍可使用 `toolbox_usage`。此入口要求绑定已授权项目内真实存在的任务，同一项目、任务和经验只计一次。`reason` 写明用途，`object_ids` 可关联对象。已经通过打卡登记的采用不重复补记。

```json
{"action":"summary","kind":"experience","days":"30"}
```

```json
{"action":"cite","id":"EXP-138","project":"<已授权项目绝对路径>","task_id":"task-000001","reason":"根据条目方法保留完整环形结构，并在当前任务中核对中心与半径","object_ids":["ring"]}
```

第二个示例的理由必须按当前任务事实填写。记录会明确标注由 Agent 报告、尚未验证，不改变经验的历史复盘或待验证建议状态。
