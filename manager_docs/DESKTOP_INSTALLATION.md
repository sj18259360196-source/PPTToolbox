# 桌面安装与 Agent 接入

## 安装

Windows 当前公开稳定版是 [1.31.26](https://github.com/sj18259360196-source/PPTToolbox/releases/tag/v1.31.26)。下载完整 Setup，先按同页 `SHA256SUMS.txt` 核对，再运行安装。Windows 1.31.30 正在准备公开发行，暂未提供公开安装包。升级后在界面版本、CLI 或 MCP 中核对实际程序与数据位置。

从本项目 Releases 选择实际已发布的 Setup 安装包，并按对应发行说明安装。公开下载版本以实际发行条目为准。应用源码由私有仓库维护。默认只为当前 Windows 用户安装，不需要管理员权限，安装时可选择程序、管理数据与默认项目目录，并创建开始菜单入口。桌面快捷方式可选。

当前 Windows 迁移版本已内置 Electron 与 Python 运行环境，无需用户另装 Python。启动入口需要 .NET Framework 4.6.2 或更高版本，安装程序会检查并提示缺失。制作和验收 PowerPoint 文件仍需本机安装 PowerPoint。

独立矢量项目使用随包引擎，无需启动 PowerPoint。具体格式由当前运行时能力决定，不应为解锁格式自行向程序目录复制依赖。创建入口与逐版管理见[矢量项目使用说明](VECTOR_SPACE.md)。

首次安装默认使用 `%LOCALAPPDATA%\Programs\PPTToolbox` 程序目录、`%LOCALAPPDATA%\PPTToolbox` 管理数据目录和用户文档目录下的 `PPTToolbox\Projects` 项目目录，可在安装时选择其他位置。已有安装继续使用原程序位置和管理数据，也保留当前项目目录设置。升级不按旧版 location.json 的项目根目录覆盖当前设置。需要搬动目录时，从设置页进入安装与迁移。

## 在 Agent 接入页完成连接

首次打开桌面窗口进入制作准备页。打开左侧 Agent 接入，上方复制通用接入提示词，发给正在使用的 Agent。Agent 识别自己的宿主和配置作用域，核对程序、管理数据与实例后使用支持的安全合并入口，其他宿主按其原生 MCP 设置接入。用户无需先选客户端。正确配置直接跳过写入，其他服务及本服务已有策略保留，来源不明、重复服务或不能安全合并时报告具体待办。

页面分别显示配置证据、本机 MCP 自检、实际客户端验证和受管 CLI 检查。下方为可选的工具箱 Agent 助手，其 API 状态单独显示。复制提示词不写入配置、不创建口令或项目，也不调用助手模型。
复制按钮旁常显并加粗本机访问前提。当前实际 MCP 或本机受管 CLI 任一可用即可，已有 MCP 无需另取文件或终端权限。两者均不可用时，先把单份通用接入词交给具备本机能力的客户端；安装软件或复制文字不会给任意既有聊天自动注入 MCP。

配置完成后按需刷新客户端 MCP。宿主无法在当前对话加载工具时，Agent 应给出重载扩展、刷新服务或新开会话的准确操作。工具实际可用时点击“生成当前对话验证请求”，复制十分钟有效、一次消费的请求，由当前对话自己的 MCP 工具调用 `toolbox_verify_connection`，随后读取 `toolbox_context`。多个请求独立保存，生成与复制不代表验证通过，也不增加第二份安装模板。未核对配置文件的通用客户端可以留下实际调用证据，同时明确配置文件未核对。口令尚未取得时保留待办，不阻止已可用通道续作。

MCP 尚未加载而 Agent 能执行本机终端时，可用当前安装生成的受管 CLI context 与 describe 检查。CLI 可用与本机 MCP 自检都不能证明当前客户端已加载工具。通过连接验证不授予项目执行权限，制作执行和新项目审批开关位于上区高级设置，仍由用户控制。
CLI 先按 manifest 的 `cli.prompt_project` 完整命令，用 `prompt-project --prompt-id` 读取编号冻结要求，再通过既有 `cli.project_open` 的 `project-open --json` 按 `project_entry_schema` 传编号、明确目录或名称、幂等键与所需素材。已绑定先 inspect，再按允许动作续作，冻结要求和设置不回写。
独立按钮“检查启动写盘”仅在明确点击时检查本机隔离样件的创建、写入、同步、原子替换、读回和清理，不运行项目、worker、Office 或模型。加载、刷新和复制不触发，原 CLI 检查仍为只读。结果不证明原项目启动成功或当前对话连接，失败时先核对诊断与原调用状态，不自动重放任务。

下区助手 API 用于查询项目和整理记录。填写此 API 不会连接外部制作 Agent，也不会让助手制作或修改 PPT。API 可达与工具调用分别检查，外部 Agent 经 MCP 或 CLI 工作时不依赖此 API。详见 [Agent 接入](AGENT_INTEGRATION.md) 和 [PPTAgent](PPTAGENT.md)。

## 更新与恢复

Agent 的正式入口固定为安装根目录下的 `agent_bridge.py`。在同一位置升级后，配置无需更改版本号或构建目录。旧的 portable.py MCP 入口继续可用。

升级退出旧后台后，已经打开的 Agent 对话可能提示 `Transport closed`。先在客户端重新连接 PPT Toolbox MCP 服务；客户端没有重连入口时，重启客户端后检查接入结果。恢复连接后查询原任务状态，再决定下一步。

安装更新前检查未决调用和项目写入锁。有未决工作时暂停更新，不强制终止。新版空闲桌面与 MCP 进程支持退出请求；旧版后台不支持时，需用户从托盘退出窗口并停止对应 MCP 服务后重试。

更新前在管理数据的 `application-updates` 中保存数据库、位置配置和被替换文件。替换失败或新运行环境导入检查失败时，回滚本次程序文件修改。断电留下 UPDATE_PENDING.json 时停止启动，保留现场供恢复处理，不静默重试。数据库备份含维护锁记录，手动恢复必须核对并释放对应维护锁，不能直接覆盖正在使用的数据库。

从 1.21.1 开始，版本与更新页可检查 GitHub Releases 并下载完整安装包，签名与文件摘要验证通过后再运行。早期版本如无法使用更新入口，需手动运行 Releases 页面实际已发布的完整 Setup。没有网络时仍可使用已安装版本。首次公开安装包尚未使用 Microsoft Authenticode 证书，Windows 可能显示未知发布者提示。

## 卸载

Windows 的已安装应用列表提供卸载入口。卸载前检查运行进程和未决任务。卸载只删除发行清单中的程序文件、快捷方式和卸载入口，保留全部管理数据、PPT 项目和用户自己放入的文件。

位置与产品标识会保留，便于再次安装时找回原数据。Agent 配置也保留；卸载后该连接暂不可用，重装到同一位置可恢复。无需保留接入时，可在客户端删除 `ppt_toolbox_manager` 条目。
